Phase 1 · RAG 刚需闭环 + 生产级项目 1 · 第 30/168 天

RAG 评测实战：Recall@K / nDCG / LLM-as-Judge 三层指标 + 改造前后对比报告

总预估时长：约 60 分钟（为什么必须评测 8min / 评测集构建 10min / 检索层指标 Recall@K 与 nDCG 14min / 生成层 RAGAS 指标 10min / LLM-as-Judge 8min / A/B 对比实战与 Java 实现思路 8min / 面试要点 2min）。主线 Java（Spring AI），Python/RAGAS 仅作评测辅助。

一、为什么必须评测：Phase 1 验收要的是数字（8min）

Phase 1 验收标准写得很硬："评测报告有改切分 / 加 rerank 前后的真实对比数字（如 Recall@5 从 62% → 89%）"。没有评测，你说"我加了混合检索效果变好了"只是感觉；有了评测，你说的是"Recall@5 62% → 89%，代价是 P99 延迟 +180ms"——这是生产级与 demo 的分水岭，也是面试量化叙事的弹药。

RAG 评测（RAG Evaluation）回答三个问题：检索找得全不全（召回）、排得对不对（排序）、答得忠不忠实（生成）。三层指标各管一层，类似测试金字塔：单元测试（检索指标）跑得快、成本低；集成测试（生成指标）慢但更接近用户体验。

二、评测集构建：先有金标，再谈指标（10min）

金标集（golden set / golden test set）：一组人工确认过正确答案的测试样本，是所有指标的分母。每条至少三字段——问题、标准答案、相关片段（标注哪几个 chunk 含答案）。20 题起步即可，来源两类：

  • 真实用户问题（最好，覆盖真实分布）；
  • LLM 从知识库文档反向生成问题（合成数据，快速上量，但需抽查质量）。
// 评测集条目：金标三件套 + 可选的分级相关性
public record EvalItem(
        String question,          // 问题
        String referenceAnswer,   // 标准答案（人工确认）
        List<String> relevantDocIds, // 标注的相关片段（Recall 的分母）
        int relevanceGrade        // 分级相关性 0-3（nDCG 用）
) {}
工程习惯：金标集放进 git 版本化（如 eval/golden-20.json），每次改切分/换 Embedding 跑回归——这就是面试里说的 "golden test set 回归测试"。

三、第一层·检索指标：Recall@K 与 nDCG（14min）

3.1 Recall@K：找全了吗

Recall@K：前 K 个检索结果里命中了多少比例的相关片段。类比：MySQL 索引粗筛出 5 行，其中真正含答案的有几行——查全率。它是 Phase 1 验收标准点名的核心指标。

Recall@K = |前K结果 ∩ 相关片段| / |相关片段|

例：金标相关片段 {d1, d2, d3}，top-5 检索返回 {d1, d4, d2, d9, d7}
命中 d1、d2 -> Recall@5 = 2/3 = 0.667

3.2 nDCG：排对了吗

nDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益）：不只看"找到没有"，还给排序位置打折——相关结果排得越靠前得分越高。类比：搜索结果第一页第一位的权重远高于第三页（位置折损），再用理想排序归一化，让分数落在 0~1。

DCG@K  = sum( (2^rel_i - 1) / log2(i + 1) )   i = 1..K
nDCG@K = DCG@K / IDCG@K      IDCG = 理想排序下的 DCG

手算例（rel 取 0-3 分级）：检索返回顺序 [rel=2, rel=0, rel=3]
DCG@3  = (2^2-1)/log2(2) + (2^0-1)/log2(3) + (2^3-1)/log2(4)
       = 3/1 + 0 + 7/2 = 6.5
理想排序 [3,2,0]：IDCG@3 = 7/1 + 3/1 + 0 = 10
nDCG@3 = 6.5/10 = 0.65

MRR（Mean Reciprocal Rank，平均倒数排名）：第一个相关结果出现位置的倒数的均值，适合"只要一条对答案就够"的场景（FAQ 类）。三者的分工：Recall@K 管"全"、nDCG 管"序"、MRR 管"第一条对不对"。

四、第二层·生成指标：RAGAS 三件套（10min）

RAGAS：一个 RAG 评测框架，把生成质量拆成可自动计算的指标（核心三个）：

指标问的问题算法要点
Faithfulness（忠实度）回答有没有编造？原子陈述拆解，逐一回上下文找支撑，取比例（昨天防幻觉任务的第二道防线就是它）
Answer Relevancy（回答相关性）答非所问吗？让 Judge 从回答反向生成若干问题，与原问题算相似度
Context Precision / Recall召回的上下文干净吗/全吗？对召回片段按"是否真被用于支撑答案"加权排序；Context Recall 需要参考答案

Python 侧（辅助）RAGAS 一行跑通，产出全家桶分数；Java 主线上等价做法是用结构化输出 + Judge Prompt 自己实现 Faithfulness（昨天教程已给出 Java 版思路），评测脚本可调用 Spring AI 的 ChatClient 当 Judge。

五、第三层·LLM-as-Judge：让模型当阅卷老师（8min）

LLM-as-Judge：用一个强模型按评分标准给回答打分。关键在 Prompt 约束"只依据给定上下文 + 输出结构化分数"：

你是 RAG 系统的评测员。依据【参考答案】与【检索上下文】，
对【待测回答】从三个维度打 0-2 分并给一句理由：
1. 忠实度：陈述是否全部有上下文依据（编造=0）
2. 完整性：是否覆盖参考答案的关键点
3. 相关性：是否直接回答了问题
只输出 JSON：{"faithfulness":x,"completeness":x,"relevance":x,"reason":"..."}

坑位提醒：Judge 也可能不稳定——控制 temperature=0、给 few-shot 样例、同一回答评 3 次取多数（自一致性），分数才可信。

六、A/B 对比实战：把"改造前后"变成表格（8min）

评测管道的最终产出是一张对比表——固定金标集，只改一个变量（切分策略 or 加 Rerank），跑两轮取差值：

配置Recall@5nDCG@10FaithfulnessP99 延迟
基线：固定 500 字切分 + 纯向量62%（示意）0.58（示意）0.81（示意）120ms
实验：按标题多粒度切分 + Rerank89%（示意）0.74（示意）0.90（示意）300ms
叙事模板：报告里每个数字都带"为什么"——Recall@5 62%→89% 因为多粒度切分保留了标题语义边界；Faithfulness 上升因为引用标注约束；延迟 +180ms 是 Cross-Encoder 精排的代价，可通过只对 top-20 重排控制。这正是 Phase 1 验收"能讲清混合检索 recall 提升多少 / rerank 延迟代价"的标准答案结构。

Java 实现要点：评测管道本质是个批处理 job——遍历金标集 → 调 vectorStore.similaritySearch → 算 Recall/nDCG（纯 Java 集合运算）→ 调 ChatClient 当 Judge → 汇总输出 Markdown 表格。无需额外框架，Spring AI 自足。

七、面试要点（2min）

  • 第一梯队·RAG 评测三层指标：检索层 Recall@K / MRR / NDCG + 生成层 RAGAS 三指标（Faithfulness 最关键）+ golden test set 回归；
  • 追问点：nDCG 与 Recall 的区别（排序质量 vs 查全率）；Faithfulness 怎么算（原子陈述逐一找支撑）；Judge 稳定性怎么保证（temperature=0 + 自一致性）；评测集怎么构建（真实问题 + LLM 合成反向问题）；
  • 量化叙事：把对比表放进 GitHub README，面试时直接报数字与代价。

📝 术语表

术语一句话解释（锚定已有知识）
金标集（golden set）人工确认过答案的评测样本集，是所有指标的基准，类似固定的单元测试用例集
Recall@K前 K 个检索结果命中相关片段的比例，衡量"查全"，类比索引粗筛的命中率
nDCG给排序位置打折的检索质量分（0~1），相关结果越靠前分越高，类比搜索首页权重
MRR第一个相关结果排名倒数的均值，适合"一条对答案就够"的 FAQ 场景
分级相关性把片段标成 0-3 档（无关/弱相关/相关/核心），比二值标签更细腻，nDCG 的输入
RAGASRAG 评测框架，把 Faithfulness/相关性/上下文质量变成可自动计算的指标
Answer Relevancy从回答反向生成问题再与原问题比相似度，衡量"答没答到点上"
Context Precision / Recall召回上下文干净度（有没有混入无关片段）与完整度（关键信息有没有漏）
LLM-as-Judge用强模型按评分标准当阅卷老师，输出结构化分数与理由
自一致性（self-consistency）同一输入评多次取多数/均值，抑制 Judge 随机性
A/B 对比实验固定金标集只改一个变量跑两轮，把改造效果变成可复现的差值表
