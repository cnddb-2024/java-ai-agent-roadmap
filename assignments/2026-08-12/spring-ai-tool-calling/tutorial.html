Phase 1

Function Calling 原理：LLM 不执行函数

预计 10 min

Tool Calling（也叫 Function Calling） 是大模型应用里最基础的"动手能力"： 模型本身只会输出文本，但通过在请求中携带一组"工具描述"，它就可以在需要时输出一段结构化的"我要调用哪个函数、参数是什么"的指令， 由客户端应用真正去执行函数，再把结果送回模型，模型据此给出最终答复。

关键认知：LLM 永远不会、也无法直接执行你写的 Java 方法。 它只是根据你提供的 JSON Schema，决定是否调用、调用哪个、传什么参数；真正的函数执行发生在你自己的进程里。 这也是为什么 Function Calling 是安全的——模型无法触达任何未被显式暴露的 API。

1. 一次完整的工具调用循环（Tool Calling Loop）

  1. 客户端在请求体里通过 tools 字段上报可用工具清单（名称、描述、参数 JSON Schema）。
  2. 模型判断需要使用工具时，在响应里返回 tool_calls（而不是最终文本）， 其中包含 id、function.name、function.arguments（JSON 字符串）。
  3. 客户端根据 name 找到本地函数，解析参数并执行，得到结果。
  4. 客户端把结果以 role=tool 的消息（携带相同的 tool_call_id）追加进对话，再发一次请求。
  5. 模型结合工具结果输出最终自然语言答案；如果还需要再调工具，则循环 2-4 步。

2. 请求中携带 tools 参数（OpenAI 兼容协议示意）

{
  "model": "gpt-4o-mini",
  "messages": [
    { "role": "user", "content": "北京和东京现在天气怎么样？" }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "getCurrentWeather",
        "description": "查询指定城市的当前天气",
        "parameters": {
          "type": "object",
          "properties": {
            "city": { "type": "string", "description": "城市名称，例如 Beijing" },
            "unit": { "type": "string", "enum": ["C", "F"] }
          },
          "required": ["city"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}

3. 模型返回 tool_calls（注意：它没有执行函数）

{
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_abc123",
            "type": "function",
            "function": {
              "name": "getCurrentWeather",
              "arguments": "{\"city\":\"Beijing\",\"unit\":\"C\"}"
            }
          },
          {
            "id": "call_def456",
            "type": "function",
            "function": {
              "name": "getCurrentWeather",
              "arguments": "{\"city\":\"Tokyo\",\"unit\":\"C\"}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ]
}

上面这个响应是 Function Calling 最核心的"面试答案"：模型在一次响应里可以并行请求多个工具调用（parallel tool calls）， 客户端可以并发执行，再把所有结果回传。Spring AI 内部就是围绕这个循环做了封装。

面试题呼应 · Function Call 底层（第一梯队）：
(1) 协议层：请求带 tools + JSON Schema，响应回 tool_calls，客户端回传 role=tool 消息；
(2) 执行权：模型只"决策"不"执行"，函数运行在客户端进程；
(3) 多轮：可循环调用，也支持一次响应里并行多个 tool_call；
(4) 描述很关键：description 写不好，模型就不知道何时该调工具。

2. 天气工具：@Tool + @ToolParam

package com.example.tools;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

import java.util.Map;

@Component
public class WeatherTools {

    // 真实场景下这里会调用第三方天气 API
    private static final Map<String, String> MOCK = Map.of(
            "Beijing", "晴，26°C，东北风 3 级",
            "Shanghai", "多云，29°C",
            "Tokyo", "小雨，24°C",
            "London", "阴，18°C"
    );

    @Tool(description = "根据城市名称查询当前实时天气，返回温度、天气状况和风力信息")
    public String getCurrentWeather(
            @ToolParam(description = "中文或英文城市名称，例如 Beijing、上海") String city,
            @ToolParam(description = "温度单位，C 表示摄氏度，F 表示华氏度", required = false) String unit) {

        String key = city == null ? "" : city.trim();
        String info = MOCK.getOrDefault(key, "暂无 " + key + " 的天气数据");
        if ("F".equalsIgnoreCase(unit)) {
            return info + "（已按华氏度返回）";
        }
        return info;
    }
}
@Tool 关键属性：
name：工具名（默认取方法名，模型按此名回调，必须在同一工具集中唯一）；
description：强烈建议认真写，模型靠它判断"何时该调"；
returnDirect：为 true 时直接把工具结果返回给调用方，不再让模型二次润色（适合结构化数据）。

3. 时间工具：获取用户时区当前时间

package com.example.tools;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.context.i18n.LocaleContextHolder;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;

@Component
public class DateTimeTools {

    private static final DateTimeFormatter FMT =
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss z");

    @Tool(description = "获取当前用户所在时区的日期与时间，无参数")
    public String getCurrentDateTime() {
        ZoneId zoneId = LocaleContextHolder.getTimeZone().toZoneId();
        return LocalDateTime.now().atZone(zoneId).format(FMT);
    }

    @Tool(description = "在当前时间基础上加上 N 分钟，返回计算后的 ISO-8601 时间")
    public String plusMinutes(@ToolParam(description = "要增加的分钟数") long minutes) {
        ZoneId zoneId = LocaleContextHolder.getTimeZone().toZoneId();
        return LocalDateTime.now().plusMinutes(minutes).atZone(zoneId).format(FMT);
    }
}

4. 计算工具：把四则运算交给本地代码

package com.example.tools;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

@Component
public class CalculatorTools {

    @Tool(description = "对两个 double 数值执行加减乘除运算，op 取值 + - * /")
    public double calculate(
            @ToolParam(description = "左操作数") double a,
            @ToolParam(description = "运算符：+、-、*、/") String op,
            @ToolParam(description = "右操作数") double b) {

        return switch (op) {
            case "+" -> a + b;
            case "-" -> a - b;
            case "*" -gt; a * b;
            case "/" -> {
                if (b == 0) throw new IllegalArgumentException("除数不能为 0");
                yield a / b;
            }
            default -> throw new IllegalArgumentException("不支持的运算符: " + op);
        };
    }
}

到这里，三个工具类都是普通的 Spring Bean。下一步只需把它们"交给" ChatClient，模型就能看到并使用它们。

Phase 3

FunctionCallback 方式：编程式工具回调

预计 15 min

除了 @Tool 注解，Spring AI 还允许以编程方式构造工具回调。这在以下场景特别有用： 工具来自第三方库、需要在运行时动态生成描述、或者你已经有一个 java.util.Function 实现想直接复用。

版本提示：在 Spring AI 1.0.x 中，编程式入口为 org.springframework.ai.model.function.FunctionCallback； 从 1.1 起官方推荐使用 ToolCallback / FunctionToolCallback / MethodToolCallback， 旧 API 被标记为 deprecated。本文同时给出两种写法，方便对照迁移。

1. 旧版 API：直接实现 FunctionCallback 接口

FunctionCallback 是 Spring AI 早期函数调用的核心接口， 要求实现 getName()、getDescription()、 getInputTypeSchema() 和 call(String functionInput)。 这能帮助你真正理解工具回调的底层契约。 

package com.example.tools;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.ai.model.function.FunctionCallback;

import java.util.function.BiFunction;

/**
 * 自定义 FunctionCallback：天气查询的"手写版"。
 * 模型回传的 functionInput 是一段 JSON 字符串，
 * 我们自己负责解析、执行、再把结果序列化为字符串返回。
 */
public class WeatherFunctionCallback implements FunctionCallback {

    private static final String NAME = "getCurrentWeather";
    private static final String DESC = "查询指定城市当前天气，输入 city 字段";

    private static final String SCHEMA = """
            {
              "type": "object",
              "properties": {
                "city": { "type": "string", "description": "城市名称" }
              },
              "required": ["city"]
            }
            """;

    private final ObjectMapper mapper = new ObjectMapper();

    // 真正干活的业务函数，可以是任意 BiFunction / Service
    private final BiFunction<String, String, String> weatherService;

    public WeatherFunctionCallback(BiFunction<String, String, String> weatherService) {
        this.weatherService = weatherService;
    }

    @Override
    public String getName() {
        return NAME;
    }

    @Override
    public String getDescription() {
        return DESC;
    }

    @Override
    public String getInputTypeSchema() {
        return SCHEMA;
    }

    @Override
    public String call(String functionInput) {
        try {
            JsonNode node = mapper.readTree(functionInput);
            String city = node.path("city").asText();
            String unit = node.has("unit") ? node.get("unit").asText() : "C";
            String result = weatherService.apply(city, unit);
            return mapper.writeValueAsString(java.util.Map.of(
                    "city", city, "unit", unit, "weather", result));
        } catch (Exception e) {
            return "{\"error\":\"" + e.getMessage() + "\"}";
        }
    }
}

2. 旧版 Builder 方式：把一个 Function<I,O> 包装成 FunctionCallback

更常见的方式是让你的服务直接实现 java.util.Function，然后用 FunctionCallback.builder() 包装。Spring AI 会利用 inputType 上的字段反射生成 JSON Schema。 

package com.example.tools;

import java.util.function.Function;

public class MockWeatherService
        implements Function<MockWeatherService.Request, MockWeatherService.Response> {

    public enum Unit { C, F }

    public record Request(String location, Unit unit) {}
    public record Response(double temp, Unit unit, String condition) {}

    @Override
    public Response apply(Request req) {
        // 真实环境调用天气 API；这里用假数据
        double base = "Beijing".equalsIgnoreCase(req.location()) ? 26.0 : 20.0;
        double temp = req.unit() == Unit.F ? base * 9 / 5 + 32 : base;
        return new Response(temp, req.unit(), "Sunny");
    }
}
package com.example.config;

import com.example.tools.MockWeatherService;
import org.springframework.ai.model.function.FunctionCallback;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class LegacyFunctionConfig {

    @Bean
    public FunctionCallback weatherFunctionCallback() {
        return FunctionCallback.builder()
                .function("getCurrentWeather", new MockWeatherService())
                .description("查询指定城市的当前天气，输入 location 与 unit")
                .inputType(MockWeatherService.Request.class)
                .build();
    }
}

3. 新版 API（Spring AI 1.1+ / 2.0）：FunctionToolCallback

迁移之后，构建器从 FunctionCallback.builder().function(...) 变成了独立的 FunctionToolCallback.builder()， 接口本身也统一为 org.springframework.ai.tool.ToolCallback。 

package com.example.config;

import com.example.tools.MockWeatherService;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.ai.tool.function.FunctionToolCallback;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ToolCallbackConfig {

    @Bean
    public ToolCallback weatherToolCallback() {
        return FunctionToolCallback
                .builder("getCurrentWeather", new MockWeatherService())
                .description("查询指定城市的当前天气，输入 location 与 unit")
                .inputType(MockWeatherService.Request.class)
                .build();
    }
}

Phase 4

工具注册与多工具并行：ChatClient.tools() / ToolCallbackProvider

预计 15 min

把工具"注册"到模型有两种粒度：请求级（只在某一次 prompt 生效） 和全局级（通过 Bean / defaultTools 对所有请求生效）。

1. 请求级注册：直接把 @Tool 对象传给 ChatClient.tools()

package com.example.controller;

import com.example.tools.CalculatorTools;
import com.example.tools.DateTimeTools;
import com.example.tools.WeatherTools;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ToolChatController {

    private final ChatClient chatClient;

    // Spring Boot 自动配置会注入一个 ChatClient.Builder
    public ToolChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/ask")
    public String ask(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)
                // 一次注册三个工具，模型可按需选择，并支持并行调用
                .tools(new WeatherTools(), new DateTimeTools(), new CalculatorTools())
                .call()
                .content();
    }
}

试试这些提问，观察模型如何选择工具（甚至一次调用多个）：

  • "北京现在天气怎么样？" → 触发 getCurrentWeather
  • "现在是几点？10 分钟后呢？" → 触发 getCurrentDateTime + plusMinutes
  • "帮我算一下 (123 + 456) * 2，顺便告诉我上海天气" → 并行触发 calculate + getCurrentWeather

2. 全局默认工具：ChatClient.Builder.defaultTools()

如果某些工具（例如时间、计算）每个会话都要用，直接在 Builder 上设置默认工具， 所有通过该 ChatClient 发出的请求都会自动携带： 

package com.example.config;

import com.example.tools.CalculatorTools;
import com.example.tools.DateTimeTools;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder,
                                 DateTimeTools dateTimeTools,
                                 CalculatorTools calculatorTools) {
        return builder
                .defaultSystem("你是一个会使用工具的助手，需要实时数据或计算时请主动调用工具。")
                .defaultTools(dateTimeTools, calculatorTools)
                .build();
    }
}

3. ToolCallbackProvider：批量、动态地提供工具

ToolCallbackProvider 是一个函数式接口，返回 ToolCallback[]。它的价值在于： 可以把多个来源的工具（@Bean、扫描包、MCP Server、数据库配置等）汇总后一次性注册。 

package com.example.config;

import com.example.tools.DateTimeTools;
import com.example.tools.WeatherTools;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.ai.tool.ToolCallbackProvider;
import org.springframework.ai.tool.method.MethodToolCallbackProvider;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ToolProviderConfig {

    /**
     * MethodToolCallbackProvider 会扫描给定对象上所有 @Tool 方法，
     * 并把它们包装成 ToolCallback。
     */
    @Bean
    public ToolCallbackProvider allToolsProvider(WeatherTools weatherTools,
                                                 DateTimeTools dateTimeTools) {
        return MethodToolCallbackProvider.builder()
                .toolObjects(weatherTools, dateTimeTools)
                .build();
    }
}

随后可以把 provider 交给 ChatClient：

@GetMapping("/ask2")
public String askWithProvider(@RequestParam String q,
                              ToolCallbackProvider provider) {
    return chatClient.prompt()
            .user(q)
            .toolCallbacks(provider.getToolCallbacks())
            .call()
            .content();
}

4. 多工具并行（Parallel Tool Calls）是怎么发生的

当模型在一次响应里返回多个 tool_calls，Spring AI 的工具管理器会并发执行它们， 再把所有结果按 tool_call_id 拼回同一条消息。 对开发者而言几乎是"免费"的——只要工具本身是无状态/线程安全的，就不需要做额外工作。 

// 触发并行调用的典型提问：
String question = "请同时告诉我北京和东京的天气，再算一下 (18 + 24) * 3 等于多少";

String answer = chatClient.prompt()
        .user(question)
        .tools(new WeatherTools(), new CalculatorTools())
        .call()
        .content();

// 模型将一次返回 3 个 tool_calls：
//   getCurrentWeather(Beijing)
//   getCurrentWeather(Tokyo)
//   calculate(18, "+", 24)  -- 然后再 calculate(42, "*", 3)
// Spring AI 并发执行完，再把结果喂回模型生成最终自然语言答案。

5. 面试题呼应：MCP vs Function Call（第一梯队）

Function Call（厂商私有协议）：
• 每家大模型都有自己的字段命名（OpenAI 的 tools/tool_calls、 Anthropic 的 tools/tool_use 等）；
• 工具与应用紧耦合，换模型常常要改适配代码；
• 工具描述随请求一起发送，工具逻辑跑在调用方进程里。

MCP（Model Context Protocol，开放标准）：
• 由 Anthropic 提出、已被 Spring AI 等生态采纳的 Client/Server 协议；
• 工具（以及资源、Prompt）由独立的 MCP Server 暴露，任何 MCP Client 都可以即插即用；
• Spring AI 中可通过 spring-ai-starter-mcp-client 把远端 MCP 工具 自动适配成 ToolCallback，用法和本地 @Tool 完全一致；
• 一句话总结：Function Call 是"模型怎么调函数"的协议；MCP 是"应用怎么连工具生态"的协议。两者并不冲突，MCP 传输的底层仍然是 Function Calling。

在 Spring AI 2.0 的架构里，ToolCallingAdvisor 已经把工具循环提升为 advisor 链中的一等公民， 本地 @Tool、FunctionToolCallback 和 MCP Server 提供的工具可以混合注册、由同一个循环统一调度——这正是从"Function Call 会用"走向"Agent 工程化"的起点。
