0 写在前面：为什么用 Java 视角学 Python OOP

本任务属于 Phase 0（定向与双框架地基）的辅助任务。Python 不是主线面试考点，但它是贯穿后续 transformers / langchain 学习的辅助语言。作为 Java 开发者，你已经具备完整的 OOP 心智模型——最有效的学法不是从零学 Python，而是建立映射 + 识别差异。

本教程的编排原则：

  • 主线是 Java：每个知识点先用 Java 表达（你熟悉），再用 Python 对照（你要学的）。
  • 抓差异，不重讲：封装 / 继承 / 多态的「是什么」默认你已懂，只讲 Python 怎么不一样。
  • 可直接跑：所有 Python 代码均为可运行片段，复制即可验证。
Java 开发者一句话心智模型：Python 把 OOP 当作「可选工具」而非「默认范式」——所以语法更宽松、更灵活，但也更依赖约定（convention）而非编译器强制。读 Python 代码时，把 __init__ 当构造器、self 当显式 this、缺省访问当 public，就能快速进入。

2 继承与多态

Java 单继承 + 接口实现多态；Python 多继承 + 鸭子类型（Duck Typing）实现多态，且无需继承关系。

2.1 多态：接口 vs 鸭子类型

Java（接口 + 方法重写）
Python（鸭子类型，无需继承）
核心差异：Java 的多态必须依赖继承关系或接口实现，并由编译器在方法签名上约束类型；Python 的多态不依赖继承——只要对象有同名方法就能调用。代价是错误在运行时才暴露（Java 在编译期就能发现）。

2.2 继承：单继承+接口 vs 多继承+MRO

Java（单继承 + 多接口）
Python（多继承 + MRO）
Java 视角速记：Python 的「多继承 + MRO」替代了 Java「单继承 + 多接口」组合。MRO（Method Resolution Order）用 C3 线性化算法解决菱形继承的二义性——你可以把它理解为 Python 自动帮你算出「方法查找的有序链表」，用 ClassName.__mro__ 可随时查看。日常很少需要手动写多继承，读代码时知道它是怎么解析的即可。

2.3 抽象基类（对应 Java abstract / interface）

Python

抽象方法的本质区别：Java 用 abstract 关键字 + @Override 强制；Python 用 abc 模块的 @abstractmethod。Python 的重写完全隐式——只要子类定义了同名方法就算重写，没有 @Override 注解（写错方法名也不会有编译报错，需靠类型检查工具 mypy 兜底）。

5 类方法 / 静态方法 / @property

@property 对应 Java 的 getter/setter；@staticmethod 对应 Java static 方法；@classmethod 是 Python 独有，常用作「替代构造器」。

Java（getter/setter + static + 工厂）
Python（@property + @staticmethod + @classmethod）
装饰器Java 对应第一个参数 / 用途
@propertygetter（getXxx）把方法暴露成属性：t.fahrenheit 而非 t.get_fahrenheit()
@x.settersetter（setXxx）赋值时触发校验：t.celsius = 30
@staticmethodstatic 方法无 self/cls，逻辑上属于类但不依赖实例
@classmethod（无直接对应，≈ 静态工厂）第一个参数是类 cls，常用于替代构造器（多个 from_xxx）
@property 的精髓：它让你先用普通属性暴露数据，将来需要加校验时再换成 @property，而调用方代码完全不用改（t.celsius 写法不变）。这是 Python 相对 Java getter/setter 的体验优势——Java 一开始就得纠结要不要写 getter。
