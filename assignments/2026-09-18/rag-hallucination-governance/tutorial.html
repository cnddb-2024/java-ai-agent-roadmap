RAG 幻觉分层治理口述整合：检索层/生成层/数据层三层拆解与拒答设计

总预估时长：50 分钟 贯穿线任务 · 滴滴 Agent 岗二面真题（2026-08 掘金面经）· 路线图第一梯队硬骨头
① 幻觉不是单一问题 5min② 三层归因 15min③ 拒答设计 10min④ Faithfulness 悖论 8min⑤ 结构化溯源输出 8min⑥ 面试口述稿 4min

一、幻觉不是单一问题，先归因再治理（5min）

幻觉（Hallucination）——模型一本正经地编造事实，类似数据库返回了"查无此行"却拼接出来的脏数据。面试深水区答案是：先别急着说"加个 Guardrail"，而是把幻觉按根因拆成三层，每层手段与代价完全不同。你此前"引用与防幻觉实战"练的是单点手段，本篇升级为可下钻 2-3 层的归因框架。

二、三层归因：每层的信号、手段与代价（15min）

层根因识别信号治理手段代价
检索层
没找到导致编造		正确片段根本没进上下文，模型只好自由发挥Rerank 最高分低于阈值；Recall@K 测出来本来就低拒答：最高分低于阈值直接说"知识库中没有依据"，不让 LLM 强答；回头按五维排查补召回牺牲部分回答率换准确率；阈值定高了拒答过多
生成层
超发挥		上下文里有答案，但模型没用/用歪/自己加戏答案内容在检索片段中找不到对应出处Prompt 约束（只按上下文作答）+ [N] 来源编号引用 + 生成后 Faithfulness（忠实度）——答案的每句主张是否能在上下文中找到依据——核查引用约束轻微降流畅度；生成后核查多一次 LLM 调用（可用小模型裁判省成本）
数据层
忠实但错误		答案确实来自上下文，但上下文本身错误/过时/冲突同一问题不同文档说法不一致；答案过了知识截止日期来源可信度 + 知识截止日期进 metadata（元数据，入库时打的标签，类似表的冗余列）；时间敏感查询强制日期过滤；多文档交叉校验（≥2 个独立来源一致才采信）入库时多维护字段；交叉校验提高入库复杂度；不能 100% 消除
记忆锚点：检索层"没饭吃"、生成层"有饭不会吃"、数据层"饭是坏的"。三层的治理介入点分别在召回后、生成前后、入库时——这也是为什么幻觉治理是全链路工程而不是一个开关。

三、拒答设计：5 条触发条件与阈值切点（10min）

拒答（Refusal）——主动承认"我不知道"，类似接口参数校验失败时返回 400 而不是硬返回脏数据。面试要求能给出至少 5 条触发条件：

  1. Rerank 最高分低于阈值（检索层没找到）
  2. 向量相似度全部低于阈值（阈值切点：把"已知/未知"问题分开的分数线，类似风控里的拒绝线）
  3. 无直接证据：答案的主张在片段中找不到支撑句
  4. 资料冲突且无法判断权威性（两文档矛盾、可信度元数据相同）
  5. 超出知识库范围（问题类别与语料分布不匹配，如拿技术手册答财务问题）

阈值切点怎么定：用"已知答案 + 明知库里没有"两类问题构造测试集，扫不同阈值画命中率-误拒率曲线，选两 类错误代价平衡的切点（已知问题被拒 vs 未知问题硬答）。已知-未知测试集划分是这题的加分下钻点。

⚠️ 框架无内置实现，以下为业界通用手写方案（原理级，Spring AI 1.1+ 的 QuestionAnswerAdvisor 只按 topK 拼上下文，不含拒答判断）：

// 拒答判断：Rerank 分数低于阈值直接返回固定话术，不送 LLM
if (ranked.isEmpty() || maxRerankScore(ranked) < REFUSAL_THRESHOLD) {
    return Answer.refuse("知识库中暂无足够依据，建议补充资料或换个问法");
}
// REFUSAL_THRESHOLD 由"已知/未知"双测试集扫描确定（示例 0.35）

四、Faithfulness 悖论：忠实 ≠ 真实（8min）

Faithfulness 只衡量答案对检索上下文的忠实度，不衡量真实性——上下文本身错了，答案可以 100% 忠实地复述错误。这就是数据层幻觉"忠实但错误"的由来，也是面试官追问"你 Faithfulness 1.0 就没幻觉了吗"的标准陷阱。

生成后核查用 Spring AI 开箱能力，不必手写裁判 Prompt：

// Spring AI 1.1+ 开箱评测器：FactCheckingEvaluator 基于上下文核验主张是否被支撑
FactCheckingEvaluator factChecker = new FactCheckingEvaluator.Builder(chatModel)
        .build();
EvaluationRequest req = new EvaluationRequest(query, contextDocuments, answer);
EvaluationResponse resp = factChecker.evaluate(req);
// resp.getScore() 低 → 生成层幻觉嫌疑；此时若上下文本身有据且互相印证
// → 疑似数据层问题，走交叉校验与来源可信度复核
面试下钻句："Faithfulness 高只说明'没超纲'，要保证真实还需数据层治理——所以我的评测是检索 Recall@K + 生成 Faithfulness + 数据交叉校验三层合看的。"

五、结构化溯源输出：比 [N] 编号更可机检（8min）

引用溯源的工程化升级版：让模型输出结构化 JSON（结构化输出——强制模型按 Schema 返回可解析数据，类似接口响应体契约），系统逐条校验：

{
  "answer": "支持蓝绿索引切换需先双写……",
  "statements": [
    {"claim": "新旧索引并行期用 alias 切换查询指针",
     "source_ids": ["doc-17#chunk-3"],
     "confidence": 0.92}
  ]
}

系统侧校验两条规则：source_ids 必须真实存在（防编造来源）；confidence 低于 0.6 的主张触发规则复核或人工抽检。Java 侧用 Spring AI 1.0+ 开箱的 StructuredOutputConverter（按 Java 类定义映射 JSON Schema）解析，校验逻辑为普通业务代码。

六、面试口述稿（4min）

90 秒版："幻觉我按根因拆三层：检索层没找到导致编造——Rerank 最高分低于阈值就拒答，不让模型强答；生成层超发挥——Prompt 接地约束加 [N] 编号引用，生成后用 Spring AI 的 FactCheckingEvaluator 核查忠实度；数据层'忠实但错误'——上下文本身错或过时，用来源可信度、截止日期元数据和多文档交叉校验治理。特别说明 Faithfulness 只管忠实不管真实，所以三层必须合看。拒答阈值用已知/未知双测试集扫描定切点。这套在项目里把点踩率从 X 降到 Y。"

📝 术语表（本篇解释过的非白名单术语）

  • 幻觉（Hallucination）：模型编造事实；按根因分检索层/生成层/数据层三层。
  • Faithfulness（忠实度）：答案逐句主张能否在检索上下文找到依据；只管忠实不管真实。
  • 拒答（Refusal）：无足够依据时主动承认"不知道"，类似参数校验失败返回 400 而非脏数据。
  • 阈值切点：用已知/未知双测试集扫描出的"回答 vs 拒答"分数线。
  • metadata（元数据）：入库时打的标签字段（来源可信度/截止日期），用于数据层归因与过滤。
  • 结构化输出：强制模型按 JSON Schema 返回，类似接口响应体契约，可被程序直接校验。
  • FactCheckingEvaluator：Spring AI 1.1+ 开箱的忠实度评测器（LLM-as-Judge 范式，用一次模型调用当裁判）。
