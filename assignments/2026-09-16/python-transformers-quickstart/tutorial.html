1 为什么 Java 开发者需要学 transformers

作为 8 年 Java 后端、Python 入门中的开发者，你已经在 Phase 1 用 Spring AI 的 ChatClient、EmbeddingModel 搭起了 RAG 骨架。但当你深入 RAG 刚需闭环时，会发现一个现实瓶颈：Spring AI 的 TransformersEmbeddingModel 底层跑的是 ONNX 模型，而模型的导出、调试、选型几乎全部发生在 Python 生态。

HuggingFace transformers 是 Python 侧最大的模型推理库（截至 2026 年 9 月最新版本 v5.15.x）。你可以把它理解为「模型界的 Spring Boot Starter」——它封装了从下载模型、分词、前向推理到后处理的全流程，让你用三行代码就能跑通一个 LLM 或嵌入模型。

Java 开发者视角

Spring AI 的 TransformersEmbeddingModel 做的事情，正是 transformers 在 Python 做的事情的「Java 移植版」。但 Java 侧只能跑已导出为 ONNX 格式的静态模型；而 Python 侧的 pipeline()、AutoModel 能直接加载原始 HuggingFace 模型做推理、微调、导出。掌握 Python 侧，你才能在选型、调试、ONNX 导出环节不被卡住。

本教程要回答的核心问题

  • 嵌入侧：Python SentenceTransformer.encode() 怎么等价于 Java EmbeddingModel.embed()？
  • 生成侧：pipeline("text-generation") 怎么类比 ChatClient.call()？
  • 工程侧：pip install 怎么类比 pom.xml？FAISS 怎么类比 Redis 向量检索？

2 pipeline 三分钟上手（文本生成 + 嵌入）

pipeline（待观察词，需解释）是 transformers 提供的最高层封装 API。类比理解：就像 Spring AI 的 ChatClient 把「构造 Prompt → 调用模型 → 解析响应」全流程封装好，pipeline() 把「加载分词器 → 加载模型权重 → 前向推理 → 后处理」全流程封装好。你只需指定任务类型和模型名，剩下的它全包。

2.1 环境准备

bash
pip install transformers sentence-transformers faiss-cpu torch

验证版本（transformers 最新 v5.15.x）：

python
import transformers
print(transformers.__version__)

2.2 文本生成：Qwen2.5-0.5B-Instruct

Qwen2.5-0.5B-Instruct 是通义千问的 0.5B 参数指令微调模型，体积小（约 1GB）、可在 CPU 跑，适合本地快速验证。它等价于 Java 侧用 Spring AI ChatClient 调用一个本地小模型做对话。

python
from transformers import pipeline

gen = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
result = gen("请用一句话介绍 Spring Boot", max_new_tokens=64)
print(result[0]["generated_text"])
Java 类比

上面三行等价于 Spring AI 中：String reply = chatClient.prompt("请用一句话介绍 Spring Boot").call().content();。区别在于 Python 侧模型权重在本地推理，Java 侧通常调远程 API（OpenAI / Ollama）。

2.3 指令模型用 chat template（推荐）

指令微调模型（Instruct）期望特定的对话格式。chat template 是 tokenizer 自带的方法，把 [{role, content}] 列表自动拼接成模型能理解的 prompt 字符串——类比 Spring AI 用 Prompt + SystemMessage / UserMessage 组装消息。

python
from transformers import pipeline

gen = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
messages = [
    {"role": "system", "content": "你是 Java 后端架构助手"},
    {"role": "user", "content": "用一句话解释 RAG"},
]
prompt = gen.tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True
)
result = gen(prompt, max_new_tokens=64, do_sample=True, temperature=0.7)
print(result[0]["generated_text"])

2.4 特征抽取 / 嵌入：feature-extraction

pipeline("feature-extraction") 返回 token 级别的隐藏状态向量，形状为 [batch, seq_len, hidden_dim]。这对应 RAG 中「把文档变成向量」的第一步。注意：这是最底层的嵌入方式，输出未做 mean pooling（均值池化），生产中通常直接用下一章的 sentence-transformers 更方便。

python
from transformers import pipeline

extract = pipeline("feature-extraction", model="BAAI/bge-large-zh-v1.5")
vec = extract("Java 开发者如何快速上手 Python")
print(len(vec[0][0]))  # 1024 维（BGE-large 的 hidden_dim）
注意

feature-extraction 输出是三维张量，每个 token 对应一个向量。要得到句子级嵌入需要做 mean pooling。生产环境推荐直接用 sentence-transformers，它内置了 pooling + 归一化。

3 AutoTokenizer + AutoModel 深入（面向 Java 开发者类比）

AutoTokenizer 和 AutoModel（待观察词，需解释）是 pipeline 内部的两个核心组件。理解它们，你就能明白 Spring AI TransformersEmbeddingModel 为什么需要同时配置 tokenizer.uri 和 onnx.model-uri 两个文件。

3.1 两个组件的职责拆解

组件职责Java 类比
AutoTokenizer 把文本切分成 token id 数组，输出 input_ids + attention_mask 类似 Jackson 的 ObjectMapper 把 JSON 字符串反序列化为对象；也类似 Spring AI 中的 tokenizer.json 文件
AutoModel 加载模型权重张量，做前向推理，输出隐藏状态 类似从 classpath 加载 .onnx 模型文件并执行推理

3.2 分词与推理全流程代码

python
from transformers import AutoTokenizer, AutoModel

# 1. 加载 tokenizer（类比 Jackson ObjectMapper，文本到 token id）
tokenizer = AutoTokenizer.from_pretrained("BAAI/bge-large-zh-v1.5")

# 2. 加载模型权重（类比从 classpath 加载 .onnx 文件）
model = AutoModel.from_pretrained("BAAI/bge-large-zh-v1.5")

# 3. 编码文本，得到 input_ids + attention_mask
inputs = tokenizer("RAG 检索增强生成", return_tensors="pt")
print(inputs.keys())  # dict_keys(['input_ids', 'attention_mask'])

# 4. 模型前向推理，得到 last_hidden_state
outputs = model(**inputs)
print(outputs.last_hidden_state.shape)  # [1, seq_len, 1024]

3.3 关键输出字段解释

字段含义Java 类比
input_ids 白名单外词。tokenizer 把文本切分后映射成的整数 id 数组，每个整数代表一个 token。类比：把中文句子拆成「词」再查字典得到行号 类似序列化后的 byte 数组，模型只认数字不认字符
attention_mask 白名单外词。与 input_ids 等长的 0/1 数组，标记哪些位置是真实 token（1）、哪些是填充位（0）。类比 SQL 的 WHERE 过滤：模型只「注意」值为 1 的位置 类似定长数组的 validLength 标记
last_hidden_state 模型最后一层输出的向量矩阵，形状 [batch, seq_len, hidden_dim] 类似 ONNX 模型推理输出的特征矩阵
padding 与 batch

批量编码多段文本时，tokenizer 会自动补齐短文本（padding），此时 attention_mask 区分真实 token 和填充位。Spring AI 侧遇到 Supplied array is ragged 报错时，正是需要开启 tokenizer.options.padding=true。

3.4 精度与设备配置

生产中常需要控制模型加载的精度和设备，以下是白名单外词的解释：

  • bfloat16（白名单外词）：一种 16 位浮点格式（Brain Float 16），类比 Java 的 float（32 位）的精简版。用 bfloat16 加载模型可将显存占用减半，精度损失极小。AutoModel.from_pretrained(..., torch_dtype="bfloat16")
  • device_map（白名单外词）：指定模型加载到哪个设备（CPU/GPU/多卡），类比 JVM 的内存分配策略。device_map="auto" 让 transformers 自动选择最优设备
python
from transformers import AutoModel

model = AutoModel.from_pretrained(
    "BAAI/bge-large-zh-v1.5",
    torch_dtype="bfloat16",
    device_map="auto",
)

4 sentence-transformers 在 RAG 中的应用

sentence-transformers（待观察词，需解释）是专门做句子级嵌入的库，它在 transformers 之上封装了 pooling（池化）和归一化，让「一段文本 → 一个固定维度向量」一步到位。这是 RAG 检索的核心组件，等价于 Spring AI 的 EmbeddingModel。

4.1 BGE 嵌入 + FAISS 向量检索完整示例

BAAI/bge-large-zh-v1.5 是智源研究院开源的中文嵌入模型，1024 维，在中文 MTEB 排行榜表现优秀。FAISS（待观察词，需解释）是 Facebook 开源的向量检索库，类比 Redis 做缓存、Elasticsearch 做全文检索——FAISS 做的是「向量相似度检索」。

python
from sentence_transformers import SentenceTransformer
import faiss
import numpy as np

# 加载中文嵌入模型（类比 Spring AI TransformersEmbeddingModel）
model = SentenceTransformer("BAAI/bge-large-zh-v1.5")

# 语料库（类比 RAG 中的知识库文档）
docs = [
    "Spring Boot 自动配置原理",
    "Redis 缓存穿透与击穿",
    "MySQL 索引优化实战",
    "RAG 检索增强生成架构",
]

# 批量编码 + 归一化
# normalize_embeddings=True：将向量归一化到单位长度，
# 这样内积等价于余弦相似度，类比 MySQL 索引前的数据标准化
embeddings = model.encode(docs, normalize_embeddings=True).astype("float32")

# 构建 FAISS 索引
# IndexFlatIP = 精确内积检索，归一化后等价于余弦相似度
dim = embeddings.shape[1]  # 1024
index = faiss.IndexFlatIP(dim)
index.add(embeddings)

# 查询检索
query = "什么是缓存穿透"
query_vec = model.encode([query], normalize_embeddings=True).astype("float32")
scores, indices = index.search(query_vec, k=2)

for rank, idx in enumerate(indices[0]):
    print(f"Top{rank+1}: {docs[idx]} (score={scores[0][rank]:.4f})")
Java 类比

上面整个流程等价于 Spring AI 的 RAG 检索：SentenceTransformer.encode() = EmbeddingModel.embed()；faiss.IndexFlatIP = VectorStore（如 PgVector / Chroma / Redis Vector Store）；index.search() = vectorStore.similaritySearch()。

4.2 normalize_embeddings 详解

normalize_embeddings（白名单外词，首次解释）：将嵌入向量缩放为单位长度（模为 1）。归一化后，向量内积与余弦相似度等价，可以用更快的内积运算（IndexFlatIP）替代余弦相似度计算。类比：MySQL 中对字段做规范化处理后再建索引，确保比较标准统一。

设置向量模长推荐检索方式
normalize_embeddings=True1.0IndexFlatIP（内积，快）
normalize_embeddings=False不确定IndexFlatL2（欧氏距离）

4.3 查询指令前缀（BGE 特有）

BGE 模型对查询需要加指令前缀以提升检索效果，这是 BGE 系列模型的特殊要求：

python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-large-zh-v1.5")

# 语料编码不需要前缀
doc_vecs = model.encode(["文档内容"], normalize_embeddings=True)

# 查询编码需要加指令前缀
query = "为这个句子生成表示以用于检索相关文章：什么是缓存穿透"
query_vec = model.encode([query], normalize_embeddings=True)

JavaDocRAG（Python transformers 对照标杆）即采用此架构：Python 3.11 + FastAPI + FAISS + sentence-transformers + BGE + BM25/RRF/cross-encoder + CLIP，是混合检索生产级范例。Spring AI Alibaba 官方示例集（evaluation-example / chat-memory-example / observability-example）则是 Java 侧的对照实现。

5 Spring AI EmbeddingModel 对照（Java 侧等价实现）

现在把 Python 侧的嵌入能力「翻译」回你的主战场 Java。Spring AI 2.0 提供了 TransformersEmbeddingModel，它用 ONNX Runtime 和 DJL 在 JVM 内本地计算嵌入，不需要调远程 API。

5.1 两个白名单外概念解释

  • ONNX Runtime（白名单外词）：跨平台机器学习推理引擎，由微软开源。它执行 .onnx 格式的模型文件，类比 JVM 执行 .class 字节码——「一次导出，到处运行」。Spring AI 用 ONNX Runtime 的 Java 版在 JVM 内跑模型推理。
  • DJL（白名单外词，全称 Deep Java Library）：AWS 出品的 Java 深度学习库，提供 Java 侧的模型加载、张量操作能力。Spring AI 用 DJL 来处理 tokenizer 和张量转换，再交给 ONNX Runtime 做实际推理。

5.2 第一步：把 Python 模型导出为 ONNX

Spring AI 不能直接加载 HuggingFace 原始模型，需要先用 Python 的 optimum-cli 把模型导出为 ONNX 格式。这一步是 Python 辅助 Java 的典型场景：

bash
python3 -m venv venv
source ./venv/bin/activate
pip install optimum onnx onnxruntime sentence-transformers
optimum-cli export onnx --model sentence-transformers/all-MiniLM-L6-v2 onnx-output-folder

导出后 onnx-output-folder 目录下会有 tokenizer.json 和 model.onnx 两个文件，这正是 Spring AI 需要的。

5.3 第二步：Maven 依赖（pom.xml）

xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-transformers</artifactId>
</dependency>

5.4 第三步：application.properties 配置

properties
spring.ai.model.embedding=transformers
spring.ai.embedding.transformer.onnx.model-uri=https://huggingface.co/intfloat/e5-small-v2/resolve/main/model.onnx

spring.ai.embedding.transformer.tokenizer.options.padding=true
配置说明

上面直接引用 HuggingFace 上已导出好的 ONNX 模型（intfloat/e5-small-v2）。也可以用本地路径 file: 或 classpath classpath:/。padding=true 解决批量编码时的 ragged array 报错。

5.5 第四步：使用 EmbeddingModel（Spring AI 2.0 接口）

Spring AI 的 EmbeddingModel 接口核心方法：embed(String text) 返回 float[]，embed(List<String> texts) 返回 List<float[]>，完全等价于 Python 的 SentenceTransformer.encode()。

java
@RestController
public class EmbeddingController {

    private final EmbeddingModel embeddingModel;

    public EmbeddingController(EmbeddingModel embeddingModel) {
        this.embeddingModel = embeddingModel;
    }

    @GetMapping("/embed")
    public Map<String, Object> embed(@RequestParam String text) {
        // 单文本嵌入，等价 Python SentenceTransformer.encode([text])
        float[] vector = embeddingModel.embed(text);
        return Map.of("dimensions", vector.length, "preview", vector[0]);
    }

    @GetMapping("/batch-embed")
    public List<Integer> batchEmbed(@RequestParam List<String> texts) {
        // 批量嵌入，等价 Python model.encode(docs)
        List<float[]> results = embeddingModel.embed(texts);
        return results.stream().map(v -> v.length).toList();
    }
}

5.6 手动配置（不使用 Spring Boot 自动装配）

java
@Bean
public EmbeddingModel embeddingModel() {
    TransformersEmbeddingModel model = new TransformersEmbeddingModel();
    model.setTokenizerResource(
        "https://huggingface.co/intfloat/e5-small-v2/raw/main/tokenizer.json");
    model.setModelResource(
        "https://huggingface.co/intfloat/e5-small-v2/resolve/main/model.onnx");
    model.setResourceCacheDirectory("/tmp/spring-ai-onnx");
    model.setTokenizerOptions(Map.of("padding", "true"));
    model.afterPropertiesSet();
    return model;
}
必须调 afterPropertiesSet()

手动创建 TransformersEmbeddingModel 时，必须调用 afterPropertiesSet()（类比 Spring 的 @PostConstruct）。如果用 @Bean 方式，Spring 容器会自动调用，无需手动调。首次 embed() 会下载并缓存 ONNX 模型（类似首次 Maven 构建下载依赖）。

7 面试口述要点

路线图面试题：Python transformers 与 Java 生态的桥接（面试加分项）。以下是要点卡片，建议按序口述。

要点 1：两边各跑什么

Python transformers 负责「模型选型、快速验证、ONNX 导出、微调调试」；Spring AI 的 TransformersEmbeddingModel 负责「JVM 内生产推理」。Python 是研发侧工具，Java 是生产侧运行时。

要点 2：嵌入接口等价关系

Python SentenceTransformer.encode(texts, normalize_embeddings=True) 等价于 Spring AI embeddingModel.embed(texts)，两者都是「文本列表 → 浮点向量列表」。区别：Python 用 PyTorch 推理原始模型权重，Java 用 ONNX Runtime 推理导出后的静态计算图。

要点 3：pipeline 的本质

pipeline() 是 AutoTokenizer + AutoModel + 后处理的三合一封装，类比 Spring AI 的 ChatClient 把 Prompt 构造、模型调用、响应解析一体化。拆开 pipeline 就能看到分词和推理两个独立步骤。

要点 4：ONNX 是桥接关键

ONNX 格式是跨语言推理的桥梁。Python 用 optimum-cli 导出 ONNX，Java 用 ONNX Runtime + DJL 加载推理。这就像 Java 编译成 .class 字节码后，JVM 跨平台执行一样——模型一次导出，Java/Python/C++ 都能跑。

要点 5：FAISS vs Spring AI VectorStore

Python 用 FAISS（IndexFlatIP）做向量检索，Java 用 Spring AI VectorStore 抽象（PgVector / Redis / Chroma）。两者底层都是计算向量相似度，FAISS 更底层高性能，Spring AI VectorStore 更高层集成 Spring 生态。

要点 6：归一化的工程意义

normalize_embeddings=True 把向量归一化到单位长度，使内积等价于余弦相似度，可以用更快的 IndexFlatIP 替代。这是一个典型的「数学等价换来工程性能」的优化思路，面试时能体现你对检索链路的深入理解。

根据模型名自动加载对应模型权重的工厂类。类比从 classpath 加载 .onnx 模型文件。
sentence-transformers [待观察]
专门做句子级嵌入的 Python 库，在 transformers 之上封装了 pooling 和归一化。类比 Spring AI 的 EmbeddingModel。
FAISS [待观察]
Facebook 开源的向量检索库，支持亿级向量高效近邻搜索。类比 Redis 做缓存、Elasticsearch 做全文检索——FAISS 做向量相似度检索。
HuggingFace Hub [白名单外]
模型托管仓库（huggingface.co），类比 Maven Central。transformers / sentence-transformers 默认从 Hub 下载模型权重。
PyTorch [白名单外]
Meta 开源的深度学习框架，类比 Java 生态的 DL4J。transformers 底层依赖 PyTorch 做张量计算和自动求导。类比 NumPy + 自动微分引擎。
tokenizer [白名单外]
分词器，把文本切分成 token 并映射为整数 id。类比 Jackson 把 JSON 字符串反序列化为对象——这里是把自然语言变成模型能理解的数字。
input_ids [白名单外]
tokenizer 输出的 token id 整数数组，模型只认数字不认字符。类比序列化后的 byte 数组。
attention_mask [白名单外]
与 input_ids 等长的 0/1 数组，标记真实 token（1）和填充位（0）。类比 SQL 的 WHERE 过滤，让模型只关注有效位置。
bfloat16 [白名单外]
Brain Float 16 位浮点格式，类比 Java float（32位）的精简版。用 bfloat16 加载模型可减半显存，精度损失极小。
device_map [白名单外]
指定模型加载到哪个设备（CPU/GPU/多卡），类比 JVM 内存分配策略。device_map="auto" 自动选择最优设备。
normalize_embeddings [白名单外]
将嵌入向量归一化到单位长度（模为 1），使内积等价于余弦相似度。类比 MySQL 建索引前对数据做标准化。
ONNX Runtime [白名单外]
微软开源的跨平台 ML 推理引擎，执行 .onnx 格式模型。类比 JVM 执行 .class 字节码——一次导出到处运行。Spring AI 用其 Java 版做本地推理。
DJL [白名单外]
Deep Java Library，AWS 出品的 Java 深度学习库。Spring AI 用 DJL 处理 tokenizer 和张量转换，再交给 ONNX Runtime 推理。
