Phase 1 · RAG 刚需闭环 + 生产级项目 1 · 第 30/168 天

引用与防幻觉实战：RAG 回答引用溯源标注 + Faithfulness 校验 + 无依据拒答

总预估时长：约 60 分钟（幻觉两层拆解 12min / 引用溯源标注 12min / Faithfulness 校验 10min / 无依据拒答与阈值 8min / Spring AI 实战 12min / LangChain4j 与 Python 辅助 4min / 面试要点 2min）。主线 Java（Spring AI + LangChain4j 双路径），Python 仅辅助。

一、幻觉从哪来：先分层，再治理（12min）

幻觉（Hallucination）指大模型输出了"看起来很自信、但检索内容里根本没有依据"的内容。治理它的第一步不是堆 Prompt，而是分层定位——这是滴滴 Agent 岗二面真题的核心考点：幻觉拆成两层，治理手段完全不同。

幻觉层级发生位置类比 Java/MySQL 世界对应防线
检索层幻觉检索没找到相关内容，模型却硬答MySQL 查询 0 命中，业务代码却没判空、直接拿 null 拼了个"默认答案"返回防线三：无依据拒答（Rerank 最高分低于阈值直接拒答，不让 LLM 强答）
生成层幻觉检索到了证据，模型"超发挥"编了证据里没有的细节查询明明命中 3 行，代码却推断出了第 4 行不存在的数据（过度推断）防线一：[N] 引用标注 + 防线二：Faithfulness 核查
为什么分层是面试加分点：面试官问"如何规避 RAG 幻觉"，答"加 Prompt 约束"是初级答案；答"先拆检索层/生成层，再分别用拒答阈值、引用标注、生成后核查三道防线"才是生产级答案。三层防线各管一段，漏斗式过滤。

二、第一道防线：引用溯源标注（12min）

引用溯源（Citation）：让每个关键论断都能标注"它来自哪条检索片段"，实现回答可追溯。工程上分两阶段实现：

  • 阶段一·来源标记：把检索片段注入 Prompt 时，给每个片段加唯一编号（如 [1]、[2]）并附元数据（标题/URL/页码）——相当于给每行证据盖了个"行号章"；
  • 阶段二·引用生成：系统提示中要求模型在每个关键论断后标注对应来源编号，输出形如"上下文组装需控制 Token 预算[2]，并缓解 Lost-in-the-Middle[1]"。

2.1 结构化输出：让引用可被程序校验

结构化输出（Structured Output）：强制模型按约定的 JSON 格式返回答案与引用列表，而不是自由文本。这类似接口约定——调用方（Java 代码）拿到的是可反序列化的 DTO，而不是一段要正则解析的散文。Spring AI 里用 BeanOutputConverter 把生成结果自动映射成 Java record：

// 引用记录：编号 + 来源 + 原文片段，用于前端角标展示与程序校验
public record Citation(int id, String sourceTitle, String snippet) {}

// 结构化回答 DTO：答案正文 + 逐条引用
public record GroundedAnswer(String answer, List<Citation> citations) {}

有了结构化输出，"引用是否一一对应"就从人眼检查变成了单测断言：citations 里的每个 id 都必须能在本次检索片段编号中找到，否则判定为无效引用。

三、第二道防线：Faithfulness 忠实度校验（10min）

Faithfulness（忠实度）：衡量"回答中的每个陈述是否都能在检索上下文中找到依据"。RAGAS 的实现思路是原子陈述拆解（Atomic Statements——把回答切成一个个最小事实单元，类似把一个大事务拆成多条 SQL，逐条验证）：让 Judge 模型把答案拆成原子陈述，再逐一回到上下文里找支撑，全部命中才记 1 分，否则按比例扣分。

回答："公司报销需在 30 天内提交[1]，逾期需走特批流程。"
拆解：S1 = "报销需 30 天内提交"     -> 上下文[1]有 -> 支持
      S2 = "逾期需走特批流程"       -> 上下文没有 -> 幻觉！
Faithfulness = 支持数 / 总陈述数 = 1/2 = 0.5
落库建议：线上保留三类日志——用户问题、召回 chunk、Faithfulness 分数。分数持续走低的 query 模式，就是你下一轮切分/检索优化的靶子（这也是明天 RAG 评测任务的数据输入）。

四、第三道防线：无依据拒答与阈值设计（8min）

最容易被跳过、却最能止血的防线：拒答（Refusal）。当 Rerank 最高分低于阈值时，直接返回"知识库中无相关内容"，不让 LLM 强答。设计要点：

  • 阈值切点：对已知答案/未知答案两套测试集分别统计 Rerank 分数分布，取两条分布的"分水岭"作为阈值（类似用 ROC 曲线选分类阈值）；
  • 测试集划分：准备"知识库里有答案的问题"和"故意问知识库外的问题"两套集合，验证已知问题不误拒、未知问题真拒；
  • 话术：拒答不是报错，而是"未在知识库中找到相关内容，建议补充资料或换个问法"。

五、Spring AI 实战：三道防线串成一个 Service（12min）

把三道防线落进一个可运行的 GroundedRagService（检索 → 阈值拒答 → 编号上下文 → 结构化输出）：

@Service
public class GroundedRagService {

    private static final double REFUSAL_THRESHOLD = 0.35; // 拒答阈值：按测试集校准
    private static final int TOP_K = 4;

    private final ChatClient chatClient;
    private final VectorStore vectorStore;
    private final BeanOutputConverter<GroundedAnswer> converter =
            new BeanOutputConverter<>(GroundedAnswer.class);

    public GroundedRagService(ChatClient.Builder builder, VectorStore vectorStore) {
        this.chatClient = builder.build();
        this.vectorStore = vectorStore;
    }

    public GroundedAnswer answer(String question) {
        // 防线三（前置）：检索质量不够，直接拒答，不让模型强答
        List<Document> docs = vectorStore.similaritySearch(
                SearchRequest.builder().query(question).topK(TOP_K).build());
        if (docs.isEmpty() || topSimilarity(docs) < REFUSAL_THRESHOLD) {
            return new GroundedAnswer("知识库中无相关内容，无法回答该问题。", List.of());
        }

        // 防线一：来源标记——给每个片段编号，拼接带 [N] 的上下文
        StringBuilder context = new StringBuilder();
        List<Citation> citations = new ArrayList<>();
        for (int i = 0; i < docs.size(); i++) {
            Document d = docs.get(i);
            context.append("[").append(i + 1).append("] ")
                   .append(d.getText()).append("\n");
            citations.add(new Citation(i + 1,
                    (String) d.getMetadata().getOrDefault("title", "untitled"),
                    truncate(d.getText(), 80)));
        }

        // 防线一 + 二：引用生成 + 忠实度约束写进系统提示
        String systemPrompt = """
                你只能依据下面编号的上下文回答问题。
                规则：
                1. 每个事实性论断后必须标注来源编号，如 [1]。
                2. 不得使用上下文中没有的信息；没有依据就不要说。
                3. 上下文不足以回答时，明确说明信息不足。
                按给定 JSON 格式输出 answer 与 citations。
                上下文：
                %s
                """.formatted(context);

        String raw = chatClient.prompt()
                .system(systemPrompt)
                .user(question)
                .call()
                .content();
        return converter.convert(raw);
    }

    private double topSimilarity(List<Document> docs) {
        return docs.stream().mapToDouble(Document::getScore).max().orElse(0.0);
    }

    private String truncate(String text, int max) {
        return text.length() <= max ? text : text.substring(0, max) + "...";
    }
}

5.1 验收自测清单（对应任务验收标准）

  • 回答附带 [1][2] 角标且与检索片段一一对应——写一个单测遍历 citations，校验 id ∈ [1, TOP_K]；
  • 无依据时回答"知识库中无相关内容"——用知识库外问题（如"公司 2030 年战略是什么"）触发拒答分支；
  • 5 个诱导幻觉问题验证——准备含"上文未提及的流程/数字/政策"的诱导问题，检查 Faithfulness 是否拦截。

六、LangChain4j 对照与 Python 辅助（4min）

LangChain4j 路径：AiServices + RetrievalAugmentor 同样可注入带编号的内容，结构化输出用 @StructuredOutput 风格的返回类型映射（思路与 Spring AI 的 BeanOutputConverter 等价：都是"生成结果 → Java 类型"）。Python 侧（贯穿线辅助）：RAGAS 的 faithfulness 指标可直接给评测脚本用，明天评测任务会展开。

七、面试要点（2min）

  • 滴滴真题·幻觉分层治理：检索层（没找到导致编造 → Rerank 最高分低于阈值直接拒答）vs 生成层（超发挥 → Prompt 约束 + [N] 编号引用 + 生成后 Faithfulness 核查）；
  • 追问点：阈值怎么定？（已知/未知两套测试集的分数分布分水岭）；引用角标怎么校验？（结构化输出 + 单测断言 id 范围）；Faithfulness 怎么算？（原子陈述拆解，逐一找支撑，取比例）；
  • 呼应 Phase 1 验收：这套防线是企业知识库 RAG "生产级深度"的直接证据，README 里放上诱导幻觉测试结果表，面试官点开就能看到量化防线。

术语一句话解释（锚定已有知识）
幻觉（Hallucination）模型输出了检索证据里没有依据却显得自信的内容，类似业务代码在查询空结果时编了个"默认答案"
引用溯源（Citation）给每个论断标注来源片段编号 [N]，让回答像带"行号"的引用一样可追溯
结构化输出强制模型按约定 JSON 返回，相当于接口返回 DTO 而非自由文本，程序可直接反序列化校验
原子陈述（Atomic Statements）把回答拆成最小事实单元逐条验证，类似把大事务拆成多条 SQL 逐条对账
Faithfulness（忠实度）回答陈述被上下文支撑的比例，1.0 表示零超发挥
拒答（Refusal）检索质量不达标时明确说"无相关内容"，不给模型编造机会
阈值切点在已知/未知答案测试集的分数分布之间取分水岭，类似 ROC 曲线选分类阈值
Grounding（接地/依据约束）约束模型只依据给定上下文作答，不调用参数记忆
