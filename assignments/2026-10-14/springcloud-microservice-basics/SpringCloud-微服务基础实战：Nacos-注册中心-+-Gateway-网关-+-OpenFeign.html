一、单体 → 微服务：为什么 AI 项目也要拆（10min）

翻回路线图的 JD 收集表：宁波制造企业（"Spring Cloud Alibaba 分布式微服务"）、天津科技公司（"精通 Spring Boot / Spring Cloud 生态；微服务架构、分布式缓存、消息队列"）都把它列为硬性要求。你的 RAG 项目 1 目前是单体，本篇做微服务化第一步——不是为拆而拆，而是让项目 1 拥有面试可讲的分布式叙事。

三个概念先桥接到位：

  • 微服务：把单体按业务边界拆成多个独立部署的小应用。你的项目 1 天然有两条拆分线——rag-web（对话/检索，要快）和 ingest-worker（文档解析入库，就是教程 1 里的 MQ 消费者，要重）。两者资源画像完全不同，拆开各自扩容正是异步解耦的下一步。
  • 注册中心：一块所有服务启动时都来"报到"地址、调用方按名字查地址的白板，等于服务界的 DNS。没有它，服务 B 部署了 3 个实例你就要手写 3 个 IP——实例动态上下线时手写 IP 不可维护。
  • 服务发现：调用方从注册中心查询目标服务当前可用实例列表的过程。

Nacos（NAme + COnfiguration + Service）是 Spring Cloud Alibaba 生态的注册中心 + 配置中心二合一组件，可以理解为 Eureka（注册）和 Apollo（配置）的合体，也是国内 Java 微服务岗位的事实标准。SpringCloud（Spring Cloud）则是 Spring 官方的微服务全家桶抽象：它不自己做注册中心/网关，而是定义接口让 Nacos 这类实现接入——和你熟悉的"Spring Data 定义仓库接口、各数据库提供 starter"是同一套玩法。

版本对齐是第一步最大的坑：Spring Cloud Alibaba 2023.0.x 配 Spring Boot 3.2/3.3，用 BOM 统一管理（父 pom）：

<dependencyManagement>

            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>org.springframework.cloud</groupId>

            <version>2023.0.3</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
<!-- 每个业务服务的 pom -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
# rag-web 的 application.yml（ingest-worker 同理，改 port 与名字）
server:
  port: 8080
spring:
  application:
    name: rag-web          # 注册到 Nacos 的服务名，调用方按这个名字找你
  cloud:
    nacos:
      server-addr: localhost:8848
Spring Cloud 2022 版本起不再需要 @EnableDiscoveryClient 注解——旧教程里让加注解的写法已被废弃，依赖引入即自动注册（这是第 13 节"新旧做法对照"的典型：旧写法了解即可，新版本开箱注册）。启动后到 Nacos 控制台"服务管理 → 服务列表"应看到 rag-web。

三、OpenFeign 声明式调用（10min）

OpenFeign 是声明式 HTTP 客户端：写一个接口 + 注解，运行时框架自动生成动态代理帮你发 HTTP 请求。你天天在用的 MyBatis Mapper 就是这个模式——Mapper 接口没有实现类，MyBatis 动态代理把方法调用翻译成 SQL；Feign 把方法调用翻译成 HTTP 请求，且服务名自动经 Nacos 解析成真实地址 + LoadBalancer 轮询分发。

<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
// rag-web 想调用 ingest-worker 的"查询入库进度"接口：

// 1. 启动类开启 Feign 客户端扫描
@SpringBootApplication
@EnableFeignClients
public class RagWebApplication {
    public static void main(String[] args) {
        SpringApplication.run(RagWebApplication.class, args);
    }
}

// 2. 声明接口：name = 目标服务在 Nacos 里的名字（不是 IP！）
@FeignClient(name = "rag-ingest")
public interface IngestClient {

    @GetMapping("/api/ingest/status/{docId}")
    Map<String, Object> status(@PathVariable("docId") String docId);
}

// 3. 像注入普通 Bean 一样注入使用，Feign 自动完成
//    "服务名 -> Nacos 查实例 -> 负载均衡选一个 -> 发 HTTP -> 反序列化"
@RestController
@RequestMapping("/api/documents")
public class DocController {

    private final IngestClient ingestClient;

    public DocController(IngestClient ingestClient) {
        this.ingestClient = ingestClient;
    }

    @GetMapping("/{docId}/status")
    public Map<String, Object> status(@PathVariable String docId) {
        return ingestClient.status(docId);   // 写起来和本地方法调用无区别
    }
}
版本时效提示：老教程里 Feign 默认集成的 Ribbon 已被 Spring Cloud LoadBalancer 取代（2020 版起退役），现在要显式引 spring-cloud-starter-loadbalancer。看 2020 年前的 Feign 教程注意甄别。

四、Gateway 网关（12min）

Gateway 网关是系统的唯一流量入口：所有外部请求先到网关，由它按规则路由到后端服务，并在入口处统一做鉴权、限流、日志这些横切能力——可以理解为 Nginx 反向代理 + Servlet Filter 链的合体，且路由规则是 Java 代码/配置可编程的。它同时是后续"令牌桶限流实战"（SSE 流式那篇的搭档）的宿主，本篇先把路由跑通。

<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>
<!-- 网关也是服务，同样注册进 Nacos 才能用 lb:// 按名路由 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
server:
  port: 9000
spring:
  application:
    name: api-gateway
  cloud:
    nacos:
      server-addr: localhost:8848
    gateway:
      routes:
        - id: rag-web-route
          uri: lb://rag-web                # lb = 从 Nacos 按名解析 + 负载均衡
          predicates:
            - Path=/api/chat/**,/api/documents/**
        - id: ingest-route
          uri: lb://rag-ingest
          predicates:
            - Path=/api/ingest/**

路由三要素：id（规则名）、predicates（断言，什么请求走这条路由，类比路由匹配条件）、uri（转发目标）。横切能力用全局过滤器演示——记录每个经过网关的请求耗时：

@Component
public class LoggingGlobalFilter implements GlobalFilter, Ordered {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        long start = System.currentTimeMillis();
        return chain.filter(exchange).then(Mono.fromRunnable(() -> {
            ServerHttpResponse response = exchange.getResponse();
            System.out.printf("[gateway] %s %s -> %d, 耗时 %dms%n",
                    exchange.getRequest().getMethod(),
                    exchange.getRequest().getPath(),
                    response.getStatusCode().value(),
                    System.currentTimeMillis() - start);
        }));
    }

    @Override
    public int getOrder() {
        return -1;   // 数值越小越先执行
    }
}
# 验证：全部流量从网关进，路径原样转发
curl -X POST localhost:9000/api/chat -H 'Content-Type: application/json' \
     -d '{"conversationId":"u1001","question":"网关链路测试"}'
# 网关日志应打印 [gateway] POST /api/chat -> 200, 耗时 xxms
注意 Gateway 基于 WebFlux 响应式栈（返回类型是 Mono/Flux），与 Servlet 是两套编程模型——在网关里只写过滤器/路由，不要把业务逻辑塞进来；Mono.fromRunnable 相当于"响应完成后执行"的回调。后续令牌桶限流实战会在这套路由上叠加 RequestRateLimiter 过滤器。

五、验收清单与面试要点（8min）

5.1 验收清单

  • Nacos 控制台看到 api-gateway / rag-web / rag-ingest 三个服务，rag-ingest 有 2 个健康实例；
  • 请求全部从 9000 网关进入并正确路由；
  • Feign 调用成功，多实例间轮询（两次请求分别命中 8081/8082 的日志）；
  • kill 掉一个 ingest-worker 实例，Nacos 心跳剔除后 Feign 自动只调存活实例——这就是服务发现的价值。

5.2 面试高频问答

面试题30 秒答法
注册中心的原理？服务启动注册地址 + 定时心跳保活，心跳超时标记下线；调用方拉取实例列表缓存本地，变更时推送更新。本质是服务界的 DNS + 健康检查。
OpenFeign 的原理？@FeignClient 接口经动态代理生成实现，调用被翻译成 HTTP 请求；服务名经 Nacos 解析 + LoadBalancer 负载均衡，写法等价本地方法。
网关的作用？放在架构哪层？唯一流量入口：路由转发 + 横切（鉴权/限流/日志/灰度）。挡在所有后端服务之前，让业务服务不重复实现安全与流量治理。
你的 AI 项目为什么要微服务化？对话/检索（低延迟在线）与文档入库（重计算离线）资源画像不同，拆开后独立扩容：入库高峰只加 ingest-worker 实例，配合 MQ 异步解耦互不拖累。

注册中心 / 服务发现服务界 DNS：服务启动上报地址 + 心跳保活，调用方按服务名查可用实例列表。
