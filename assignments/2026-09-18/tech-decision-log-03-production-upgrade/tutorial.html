一、什么是技术决策日志，为什么收官阶段写它（5min）

技术决策日志（ADR，Architecture Decision Record）——用固定模板把"当时为什么这么选、放弃了什么、什么条件下撤销"写成短文档，类似数据库的 binlog：不只记录结果，更记录"怎么走到这一步"。你已写过 #01（向量库选型 pgvector vs Qdrant）与 #02（Rerank 方案选型），本次 #03 升格为全景盘点：对照路线图"Demo → 生产级五层升级路径"逐层评估项目 1 现状，产出"先补哪层"的决策。

这篇决策日志的产出物是一张"四栏表格 × 5 层"：现状 / 缺口 / 补齐动作 / 代价，外加优先级排序理由。它是 Phase2 工程化补齐的路线依据，也是面试里"demo 和生产差在哪"的答案素材库。

二、五层逐层评估（25min，每层 5min）

① 可靠性：失败是常态，先接住再说

栏内容
现状同步调用主链路跑通；LLM 网络抖动无重试；无超时统一配置
缺口无端到端超时与指数退避（backoff）——失败后按 1s、2s、4s 递增间隔重试，避免瞬时故障被放大成雪崩；无熔断——错误率超阈值后快速失败一段时间，像家里跳闸保护电器，Java 侧即 Sentinel/Resilience4j 的断路器概念
补齐动作Spring Retry（@Retryable）做指数退避重试；Resilience4j CircuitBreaker 按错误率熔断；容量按峰值 QPS 而非平均规划
代价重试放大流量（需配重试上限）；熔断窗口内牺牲部分可用性；开发+配置约 1-2 天

② 可观测性：没有度量就没有优化

栏内容
现状Micrometer + Actuator 已接（9-05 实战）；日志为非结构化 println 风格；无分布式追踪
缺口结构化 JSON 日志；p50/P95 延迟——把全部请求耗时排序，第 95 百分位的值，比平均值更能暴露长尾卡顿——分位统计；错误率分类（超时/限流/模型失败分开数）；每请求 token 成本；跨 HTTP→DB→LLM 的调用链
补齐动作logback JSON encoder；Micrometer Tracing（开箱，自动在 HTTP 头传播 trace 上下文）；MeterRegistry 自定义 token 计数指标（线上体验对齐实战已埋部分埋点）
代价日志量增大需配滚动策略；追踪引入轻微开销（采样率控制）；约 2-3 天

③ 安全合规：Phase1 已练一半，差工程化收口

栏内容
现状Prompt 注入三层防护已做（输入-架构-输出，9-17 实战）；无权限体系；无审计日志
缺口RBAC（基于角色的访问控制）——按角色决定"谁能调这个接口、能查哪个命名空间"，类似 Spring Security 的角色权限；多租户数据隔离（检索前按租户过滤）；操作审计留痕
补齐动作Spring Security + 方法级 @PreAuthorize；检索 FilterExpression 加租户条件（灰度发布实战同款机制复用）；审计切面记录 who/when/query
代价权限模型设计 2-3 天；过滤条件增加检索开销；多租户改造涉及数据结构

④ 质量评测：回归防线，Phase1 已有雏形

栏内容
现状RAGAS 三指标评测已跑（9-08）；线上点踩/空回答埋点已接（9-17）；评测集与线上 bad case 回流未成闭环
缺口黄金测试集（golden set）——人工确认过的标准问答对集合，类似回归测试用例库——版本化固定；每次改动的自动回归；A/B 对比实验（新旧版本各接一半流量比指标，避免"自我感觉良好"）
补齐动作评测集入库版本管理；CI 里跑 Recall@K/Faithfulness 回归门禁（低于基线即失败）；bad case 从 trace 回流评测集（线上体验对齐篇已设计）
代价评测集建设持续投入；CI 时长增加；LLM 裁判调用成本（可用小模型降级省 10 倍）

⑤ 成本与规模化：demo 不花钱，生产处处是钱

栏内容
现状无 token 预算控制；无缓存；单实例部署
缺口token 预算与成本红线（Cost Threshold）——单日花费上限，超出后降级或拒量，类似限流但对"钱"限流；每日上限告警；非实时任务（全量重嵌入）转后台队列；prompt 缓存（相同前缀复用计费与计算）
补齐动作bucket4j（令牌桶限流库，按预算当令牌发放）；嵌入与 prompt 缓存（Redis，已熟）；批任务转 RabbitMQ 异步（RabbitMQ 实战直接复用）
代价限流影响峰值体验；缓存失效策略要设计；后台化增加架构复杂度

三、优先级排序：为什么先补可靠性 + 可观测（8min）

用简化版加权决策矩阵——给每个候选打"收益×紧急度"的加权总分，代替拍脑袋排序：

候选层面试叙事价值线上风险敞口补齐成本加权结论
① 可靠性高（Agent Loop 治理同源）高（LLM 抖动必现）低（1-2 天）P0 先做
② 可观测高（p95/成本数据是后面所有决策的依据）中低-中P0 与①并行
④ 质量评测高（第一梯队 RAG 评测题）中中（评测集持续建设）P1 Phase2 前期
③ 安全合规中（注入防护已讲过，增量是 RBAC）中（演示项目租户场景弱）中P1 与④并行
⑤ 成本规模化中（口述清楚即可，动手可后置）低（个人项目调用量小）中P2 记录方案即可
排序逻辑一句话：可靠性是"别挂"，可观测是"看得见"，两者是其他三层的地基且成本低；评测与安全是"做得好"；成本在个人项目量级下风险最低。撤销条件——预先写明"什么信号出现时推翻本决策"（如：线上出现一次因无熔断引发的雪崩 → ⑤⑤成本层立即提级）——是 ADR 防腐的关键栏位。

# 决策日志 #03：项目1 生产级五层升级路径评估
日期: 2026-09-18  状态: 已采纳
## 背景
项目1 完成 Phase1 RAG 闭环，准备 Phase2 工程化补齐，需确定层级优先级。
## 评估结论（四栏表 x5 层，见正文）
## 决策
P0 可靠性+可观测（1 周内）；P1 评测+安全（Phase2 前期）；P2 成本（方案记录）。
## 放弃的方案
五层齐头并进：资源不允许且无数据支撑每层效果，先用可观测层拿到数据再迭代。
## 撤销条件
线上出现熔断缺失级联故障 / 面试目标公司 JD 显式要求 RBAC 实操经验时，对应层提级。
面试 60 秒口述："我按五层路径盘点过项目：可靠性只有同步调用没有重试熔断，可观测只有基础指标没有 p95 和成本归因，安全做了注入防护但缺 RBAC 和审计，评测有 RAGAS 但没回归门禁，成本完全没管。我决策先补可靠性加可观测——它们是地基、成本低、还是后续所有优化决策的数据来源；评测和安全放 Phase2 前期并行；成本层记录方案暂不实施。每层放弃的方案和撤销条件都写在决策日志里。"

📝 术语表（本篇解释过的非白名单术语）

  • ADR（技术决策日志）：记录"为什么这么选、放弃了什么、何时撤销"的短文档，类似 binlog 记录过程而非仅结果。
  • 指数退避（backoff）：失败重试间隔按 1s/2s/4s 递增，防止把瞬时故障打成雪崩。
  • 熔断：错误率超阈值后快速失败一段时间，像跳闸保护；Resilience4j 断路器即此概念。
  • P95 延迟：耗时排序后第 95 百分位的值，暴露平均值掩盖的长尾卡顿。
  • RBAC：按角色控制接口与数据访问，类似 Spring Security 角色权限。
  • 黄金测试集（golden set）：人工确认的标准问答对集合，相当于回归测试用例库。
  • A/B 对比实验：新旧版本各接一半流量比指标，避免主观判断。
  • 成本红线（Cost Threshold）：单日花费上限，超出即降级或拒量，"对钱限流"。
  • 加权决策矩阵：多维度加权打分替代拍脑袋排序。
  • 撤销条件：预先写明的"出现什么信号就推翻本决策"。
  • bucket4j：Java 令牌桶限流库，可把预算当令牌发放实现成本限流。
