一、requests 是什么：Python 世界的 HTTP 客户端（10min）

requests：Python 最常用的 HTTP 客户端库（对标 Java 的 OkHttp / Apache HttpClient / Spring 的 RestTemplate），一句 requests.post(url, json=payload) 完成请求，自动处理 JSON 序列化、连接复用。安装：pip install requests。

Session（会话对象）：requests 的连接池封装——同一个 Session 复用底层 TCP 连接（keep-alive），相当于 OkHttp 的连接池 + 拦截器挂载点（可统一加 header）。批量调 API 时务必用 Session，别每次裸调 requests.post（每次新建连接，慢且费端口）。

import requests

session = requests.Session()
session.headers.update({
    "Authorization": "Bearer " + os.environ["LLM_API_KEY"],  # 密钥走环境变量
    "Content-Type": "application/json",
})
# 之后所有请求复用连接池，类似 OkHttp 单例 client
resp = session.post(LLM_URL, json=payload, timeout=(5, 60))
print(resp.status_code, resp.json()["choices"][0]["message"]["content"])
Java 直觉映射：requests.Session() ≈ OkHttp 的 OkHttpClient 单例；session.headers.update(...) ≈ 添加全局拦截器统一塞 header；timeout=(5, 60) ≈ OkHttp 的 connectTimeout/readTimeout 分离设置。

二、OpenAI 兼容接口：一套协议打天下（12min）

OpenAI 兼容接口（OpenAI-compatible API）：业界事实标准——各厂商（DeepSeek、通义、Ollama 本地、vLLM 私有化部署）都提供与 OpenAI /v1/chat/completions 相同格式的接口，换 provider 只改 base_url + api_key + model 三要素。这意味着写一次脚本，可以无缝切换云端/本地模型。

import os
import requests

BASE_URL = os.environ["LLM_BASE_URL"]   # 如 https://api.deepseek.com/v1 或 http://localhost:11434/v1
API_KEY  = os.environ["LLM_API_KEY"]
MODEL    = os.environ["LLM_MODEL"]

payload = {
    "model": MODEL,
    "messages": [
        {"role": "system", "content": "你是严谨的技术助手，只依据给定资料回答。"},
        {"role": "user", "content": "用一句话解释什么是 RAG。"},
    ],
    "temperature": 0.2,     # 越低越确定（0 = 近似确定性输出）
    "max_tokens": 512,
}

resp = session.post(BASE_URL + "/chat/completions", json=payload, timeout=(5, 60))
resp.raise_for_status()     # 4xx/5xx 直接抛异常，类似 RestTemplate 的错误处理
data = resp.json()
print(data["choices"][0]["message"]["content"])

字段对照 Java：messages 就是 Spring AI 里 Prompt 的 SystemMessage/UserMessage 列表；temperature/max_tokens 与 ChatOptions 一一对应；返回的 choices[0].message.content 即 ChatResponse 的 generation 内容。

三、流式 SSE：逐 token 打印（15min）

SSE（Server-Sent Events）：服务端单向推送协议——响应头 Content-Type: text/event-stream，正文按 data: {...}\n\n 分帧，每帧一个 JSON 增量。大模型接口用它把生成过程边算边发（你已经熟悉概念，这里补 Python 解析细节）。

关键三点：stream=True 开流式；iter_lines() 逐行迭代（像 BufferedReader.readLine）；帧以 data: 前缀开头，[DONE] 是结束哨兵：

def stream_chat(session, payload):
    payload = dict(payload, stream=True)   # 开启流式
    with session.post(BASE_URL + "/chat/completions",
                      json=payload, stream=True, timeout=(5, 120)) as resp:
        resp.raise_for_status()
        for line in resp.iter_lines(decode_unicode=True):
            if not line or not line.startswith("data: "):
                continue                    # 跳过空行与注释行
            chunk = line[len("data: "):]
            if chunk == "[DONE]":           # 结束哨兵
                break
            delta = json.loads(chunk)["choices"][0]["delta"]
            piece = delta.get("content")
            if piece:
                print(piece, end="", flush=True)   # 逐 token 打印

stream_chat(session, payload)
坑位：①流式请求的 read timeout 要放宽（生成全程算 read 阶段，120s 起步）；②flush=True 别忘，否则 token 攒在缓冲区看不到"打字机效果"；③delta 里首帧可能有 role、末帧可能是 finish_reason，都要判空。Java 对照：Spring AI 的 .stream() 返回 Flux，底层就是解析同样的 SSE 帧——你写的这个解析器就是 Flux 版的手动展开。

四、超时与指数退避重试（12min）

线上脚本必须处理两类失败：瞬时错误（429 限流 / 500 / 网络抖动——值得重试）与永久错误（401 认证错 / 400 参数错——重试无意义）。策略：指数退避重试瞬时错误，永久错误立即报错。

指数退避（Exponential Backoff）：每次重试等待时间翻倍（1s→2s→4s），给服务恢复时间；加抖动（jitter，随机扰动）防止所有客户端同一时刻集体重试造成二次冲击（惊群效应）——对应 Java 里 Resilience4j 的 retry + randomizedDelay 思路。

RETRYABLE = {429, 500, 502, 503, 504}   # 瞬时错误：限流与网关类
MAX_ATTEMPTS = 4

def chat_with_retry(session, payload):
    for attempt in range(1, MAX_ATTEMPTS + 1):
        try:
            resp = session.post(BASE_URL + "/chat/completions",
                                json=payload, timeout=(5, 60))
            if resp.status_code in RETRYABLE:
                raise requests.HTTPError(f"retryable {resp.status_code}")
            resp.raise_for_status()          # 401/400 在这里直接抛出，不重试
            return resp.json()
        except (requests.ConnectionError, requests.Timeout, requests.HTTPError) as e:
            if attempt == MAX_ATTEMPTS:
                raise                        # 重试耗尽，向上抛
            backoff = min(2 ** attempt, 30)  # 2s, 4s, 8s ... 封顶 30s
            sleep = backoff * (0.5 + random.random() * 0.5)  # 加 jitter
            print(f"[retry {attempt}/{MAX_ATTEMPTS-1}] {e} -> sleep {sleep:.1f}s")
            time.sleep(sleep)

进阶可用 tenacity（Python 重试库，声明式装饰器 @retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=1, max=60))——对标 Spring Retry 的 @Retryable），OpenAI 官方文档也推荐它处理 429。
