一、DataFrame 心智模型：一张带索引的数据库表（8min）

DataFrame：pandas 的核心数据结构，一张二维表——每一列有名字、有类型（类似数据库表的列），每一行有个行号索引。对 8 年 Java 后端的你，最贴切的类比是：List<Map<String, Object>> 加上了列元信息和向量化操作；用起来更像"内存里的 MySQL 表"或"一张 Excel"。Series 则是单列（List + 名称 + 索引），DataFrame 就是若干 Series 拼起来的。

二、读写：CSV / JSON 一次到位（8min）

评测脚本最常见的活：把检索日志、金标集、模型输出读进来算指标，再把结果表写出去。这就是 pandas 的主场：

import pandas as pd

# 读 CSV（评测输出日志）
df = pd.read_csv("eval_log.csv", parse_dates=["ts"])
# 读 JSONL（每行一个 JSON：金标集常用格式）
golden = pd.read_json("golden_set.jsonl", lines=True)
# 读 Excel / 写出
df.to_csv("result.csv", index=False)
df.to_json("result.jsonl", orient="records", lines=True, force_ascii=False)

read_csv 的 parse_dates 参数类似 MyBatis 的 TypeHandler：读的时候就把字符串转成时间类型，省得后面再转。写 JSON 时 force_ascii=False 保证中文不变成 \u4e2d\u6587 转义串（默认会 ASCII 化，这是爬中文数据的人最常踩的坑）。

三、数据清洗：缺失值 / 去重 / 类型（12min）

NaN（Not a Number，缺失值标记）：pandas 用它表示"这一格没数据"，类似 Java 的 null，但行为更细：NaN 参与数值运算会传染（结果也是 NaN），所以要先处理。清洗三板斧：

# 1. 缺失值：先诊断再处理（isna() 返回布尔列，sum() 数每列缺失数）
df.isna().sum()
# 填充：分数缺失按组均值填（fillna 类似 SQL 的 COALESCE）
df["score"] = df["score"].fillna(df.groupby("city")["score"].transform("mean"))
# 或整行丢弃（像 SQL 的 WHERE score IS NOT NULL）
df = df.dropna(subset=["score"])

# 2. 去重：评测日志里重复请求会虚高指标
df = df.drop_duplicates(subset=["query", "model"])

# 3. 类型转换：read_csv 常把 ID 读成数字（丢失前导零）
df["doc_id"] = df["doc_id"].astype(str)
# 字符串规范化：去首尾空格 + 统一小写
df["query"] = df["query"].str.strip().str.lower()
桥接 Stream：Java 里 list.stream().filter(Objects::nonNull).distinct() 对应 pandas 的 dropna() + drop_duplicates()；区别是 pandas 按列批量操作且不重新分配对象链（inplace 或重新赋值）。

四、分组聚合：split-apply-combine（14min）

groupby 的 split-apply-combine 三步：先按键把表拆成若干子表（split，等价 SQL 的 GROUP BY 分组），对每个子表算统计量（apply，等价聚合函数），再把结果拼回一张表（combine）。这是数据分析的核心操作，也是你后面写评测报告按维度切片统计的基础。

# 基础：按城市分组求平均分 —— 等价 SELECT city, AVG(score) FROM t GROUP BY city
df.groupby("city")["score"].mean()

# agg：一次多指标 —— 等价 AVG + MAX + COUNT 同查
df.groupby("city").agg(
    avg_score=("score", "mean"),
    max_score=("score", "max"),
    n=("score", "count"),
)

# 多级分组：城市 × 题型两个维度
df.groupby(["city", "type"])["score"].mean()

# transform：把聚合结果广播回每一行（给"组均值填充"用，类似 SQL 窗口函数 OVER(PARTITION BY)）
df["city_avg"] = df.groupby("city")["score"].transform("mean")

# filter：整组过滤——只保留均分及格的城市（SQL 里要 HAVING 子查询，这里一行）
df.groupby("city").filter(lambda g: g["score"].mean() >= 60)

# apply：每组跑任意函数（组内 Top1：每组挑最高分那条）
df.sort_values("score", ascending=False).groupby("city").head(1)

五、RAG 场景实战：评测结果按维度切片（6min）

把前三节的技能串起来，做一个真实任务：统计 20 个评测问题在两种切分策略下的 Recall@5 差异，按问题类型分组：

import pandas as pd

log = pd.read_json("eval_log.jsonl", lines=True)
# 列：question_id, q_type, strategy, recall_at_5

# 透视表：一行一个问题类型，一列一个策略（Excel 数据透视表）
pivot = log.pivot_table(
    index="q_type", columns="strategy", values="recall_at_5", aggfunc="mean"
)
pivot["delta"] = pivot["semantic_512"] - pivot["fixed_256"]
print(pivot.sort_values("delta", ascending=False).round(3))

# 输出（delta > 0 表示语义切分更好）：
# strategy    fixed_256  semantic_512  delta
# q_type
# 多跳推理     0.52        0.81        0.29
# 事实查询     0.71        0.85        0.14
# 长文档汇总   0.43        0.47        0.04

pivot_table（数据透视表）：按两个维度交叉聚合的利器，Excel 透视表的代码版。五行代码完成"哪种问题类型从语义切分受益最大"的分析，写进评测报告就是差异化细节。对照路线图推荐项目 JavaDocRAG（Python 检索管线 + 金标准回归评测套件）——评测统计这一层它就是用这套工具做的。
