一、硬件与模型选择

显存推荐模型预期速度
4-6 GBqwen2.5:3b / qwen3:1.7b10-20 tokens/s
8 GBqwen2.5:7b / qwen3:4b15-30 tokens/s
16 GB+qwen2.5:14b / qwen3:8b20-40 tokens/s
纯 CPUqwen2.5:1.5b3-8 tokens/s（可做功能验证）

本教程以 qwen2.5:7b 为基线；显存不够请降级到 qwen2.5:3b，API 完全一致。

二、安装 Ollama 并拉取模型

Linux / macOS：

# Linux
curl -fsSL https://ollama.com/install.sh | sh

# macOS 直接下载 https://ollama.com/download

# 验证
ollama --version

# 拉取并运行（首次会下载约 4.7GB）
ollama run qwen2.5:7b

# 在交互界面输入测试
>>> 用一句话解释 RAG
RAG（检索增强生成）是在生成回答前先从外部知识库检索相关片段，再交给大模型生成答案的技术。

# 退出交互（/bye），但服务仍在后台运行
ollama list          # 查看已下载模型
ollama ps            # 查看当前加载中的模型

Ollama 默认监听 http://localhost:11434，直接 curl 验证：

curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5:7b",
  "prompt": "你是谁",
  "stream": false
}'
生产环境提示
部署到服务器时设置 OLLAMA_HOST=0.0.0.0:11434 并配合防火墙白名单；不要把 11434 直接暴露公网。Linux 上 Ollama 以 systemd 服务运行，日志用 journalctl -u ollama -f 查看。

  </dependency>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
  </dependency>

3.2 application.yml

server:
  port: 8080

spring:
  application:
    name: ollama-demo
  ai:
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: qwen2.5:7b
          temperature: 0.7
          num-ctx: 4096
      init:
        pull-model-strategy: never   # 启动时不自动拉模型
        timeout: 60s

3.3 最简 ChatClient

@RestController
@RequestMapping("/api/chat")
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @PostMapping
    public Map<String, String> chat(@RequestBody Map<String, String> req) {
        String answer = chatClient.prompt()
                .user(req.get("message"))
                .call()
                .content();
        return Map.of("answer", answer);
    }

    @GetMapping(value = "/stream", produces = "text/event-stream")
    public Flux<String> stream(@RequestParam String message) {
        return chatClient.prompt()
                .user(message)
                .stream()
                .content();
    }
}

3.4 启动并调用

# 同步
curl -X POST http://localhost:8080/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"用一句话解释 RAG"}'

# 流式
curl -N "http://localhost:8080/api/chat/stream?message=用一句话解释RAG"

四、记录显存与首 token 延迟

验收时必须记录三个数字，作为后续 Phase 1 评测报告的基线：

# 1. 显存占用（模型加载后）
nvidia-smi --query-gpu=memory.used,memory.total --format=csv

# 2. 首 token 延迟 + 总耗时
time curl -X POST http://localhost:8080/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"写一段 100 字左右的 RAG 介绍"}'

# 3. 生成 tokens/s（在 Ollama 日志中可见）
journalctl -u ollama -n 50 --no-pager | grep "eval rate"

把结果写入 summary.md：

## 本地模型基线
- 模型：qwen2.5:7b
- 显存：5.2 GB / 8 GB
- 首 token 延迟：约 180 ms
- 生成速度：约 28 tokens/s
- num_ctx：4096
- 结论：可满足 Phase 1 本地 RAG 评测需求

五、与 Phase 1 RAG 链路对接

这个本地模型后续会接入三个地方：

  1. Embedding：再拉一个 nomic-embed-text 或 qwen3-embedding:8b，Spring AI 用 OllamaEmbeddingModel 接入。
  2. RAG 生成：通过 ChatClient + QuestionAnswerAdvisor 把检索到的上下文拼进 prompt。
  3. 评测：用本地模型跑 LLM-as-Judge 不花钱，Phase 1 评测报告中的"改切分/加 rerank 前后对比"就靠它。

六、验收清单

  • ollama list 能看到 qwen2.5:7b（或你选的型号）
  • Spring Boot 启动无报错，/api/chat 返回正常文本
  • 流式接口 /api/chat/stream 能看到逐字输出
  • summary.md 中记录了显存、首 token 延迟、生成速度三个数字
  • 能用一句话口述："我本地跑的是 qwen2.5:7b，显存占 X GB，速度 Y tokens/s"
