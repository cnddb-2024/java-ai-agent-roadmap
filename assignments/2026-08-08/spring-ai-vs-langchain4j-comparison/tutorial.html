01核心洞察：分层互补，不是二选一

面试官最想听到的不是"哪个更好"，而是你对两者定位差异的理解。请先记住下面这句话，它是整个口述的"定调句"。

一句话定调
Spring AI 是"企业集成基础设施层"，LangChain4j 是"灵活 LLM 工具箱"，两者分层互补，并非互斥二选一。
在企业 Spring 体系中，可以让 Spring AI 承担配置治理、可观测性与安全编排，而把 LangChain4j 作为独立 Agent / PoC 服务的实现库；大型组织完全可以混用。
SPRING AI

Portable Service Abstraction（可移植服务抽象）

Spring 官方出品，把 AI 能力作为 Spring 生态的"一等公民"。像当年抽象 JDBC / JMS 一样抽象底层模型，换模型只改配置不改代码。

  • 设计理念：约定优于配置，配置驱动
  • 核心价值：与 Boot / Security / Actuator / Micrometer 深度集成
  • 适合：已有 Spring 体系、长期维护、强治理要求
LANGCHAIN4J

Java 原生 LLM 编排库（框架无关）

社区驱动，借鉴 Python LangChain 但为 JVM 从零设计。不绑定 Spring，可用于 Quarkus / Micronaut / 纯 Java，启动快、耦合低。

  • 设计理念：灵活组合，声明式 AI Services
  • 核心价值：功能全面、迭代快、跨框架
  • 适合：快速原型、独立 Agent、非 Spring 项目

口述技巧：先用"定调句"亮明观点，再用两个标签词（基础设施层 vs 工具箱）锚定差异，最后给一句"可以混用"展现工程视野。这样比直接背功能表更稳。

03Spring AI 核心 API 速览

五大核心：ChatClient、Advisors、Tool Calling、MCP、Micrometer 可观测性。每个都配最小可运行示例，主线语言 Java 21 + Spring Boot。

3.1 ChatClient —— 流式 Fluent API

ChatClient 是 Spring AI 的中枢入口，风格类似 WebClient / JdbcTemplate：.prompt().system().user().call().content() 一步步链式表达，显式且可读。

JavaChatService.java复制
@Service
public class ChatService {

    private final ChatClient chatClient;

    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String chat(String userMessage) {
        return chatClient.prompt()
                .system("你是企业 AI 助手，回答专业、简洁。")
                .user(userMessage)
                .call()
                .content();
    }
}

3.2 Advisors —— 拦截器链（核心扩展点）

Advisor 是 Spring AI 的"灵魂"：以链式拦截器方式在请求前后插入逻辑（RAG 检索、记忆注入、Token 追踪、日志等）。内置 QuestionAnswerAdvisor（RAG）、MessageChatMemoryAdvisor（记忆）、ToolCallingAdvisor（工具）等。

JavaRagService.java — QuestionAnswerAdvisor 实现 RAG复制
@Service
public class RagService {

    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public RagService(ChatClient.Builder builder, VectorStore vectorStore) {
        this.vectorStore = vectorStore;
        this.chatClient = builder
                .defaultAdvisors(
                    QuestionAnswerAdvisor.builder(vectorStore)
                        .searchRequest(SearchRequest.builder()
                            .topK(5)
                            .similarityThreshold(0.7)
                            .build())
                        .build())
                .build();
    }

    public String ask(String question) {
        return chatClient.prompt().user(question).call().content();
    }
}

3.3 Tool Calling —— 函数 / 工具调用

把普通 Java 方法注册为工具，ChatClient 自动生成 JSON Schema 并在模型需要时回调执行。可注解式 @Tool，也可用 Function Bean。

JavaWeatherTools.java — @Tool 注解式复制
public class WeatherTools {

    @Tool(description = "查询指定城市的实时天气")
    public WeatherResponse getWeather(String city) {
        return weatherService.query(city);
    }
}

// 在 ChatClient 调用时传入工具
String answer = chatClient.prompt()
        .user("北京今天天气怎么样？")
        .tools(new WeatherTools())
        .call()
        .content();

3.4 MCP —— Model Context Protocol

MCP 是 Anthropic 提出的"工具协议标准"。Spring AI 提供 Client / Server 两端 Boot Starter，自动发现并聚合 MCP Server 暴露的工具为 SyncMcpToolCallbackProvider Bean，实现跨进程工具复用。

YAMLapplication.yml — MCP Client 配置复制
spring:
  ai:
    mcp:
      client:
        sse:
          connections:
            weather-server:
              url: http://localhost:8081
        stdio:
          servers-configuration: classpath:mcp-servers.json
    # 自动装配后，所有 MCP 工具聚合为 SyncMcpToolCallbackProvider Bean
    # 注意：MCP 工具不会自动注册到 ChatClient，需手动 .tools(mcpProvider) 注入

3.5 Micrometer 可观测性 —— 原生指标 + 链路追踪

这是 Spring AI 对 LangChain4j 的最大优势。接入 spring-boot-starter-actuator 即自动获得：Token 用量、响应耗时、错误率等指标，以及跨 HTTP→DB→模型 API 的分布式追踪。无需写一行监控代码。

YAMLapplication.yml — 可观测性配置复制
spring:
  ai:
    chat:
      client:
        observations:
          log-prompt: true      # 记录 prompt 内容（注意脱敏）
          log-completion: true # 记录模型返回内容
    chat:
      observations:
        log-prompt: true
# 自动产出指标：gen_ai.client.token.usage（输入/输出 token）、
# gen_ai.client.operation（模型调用耗时）、spring.ai.advisor（Advisor 链路 span）
Span / 指标名含义关键属性
spring.ai.chat.clientChatClient 调用（call/stream）是否流式、Advisor 列表、会话 ID
spring.ai.advisorAdvisor 链路每一步Advisor 名称、执行顺序
gen_ai.client.operation模型 Provider 执行模型名、耗时、finish_reason
gen_ai.client.token.usageToken 用量input_tokens / output_tokens / total
spring.ai.tool工具调用执行工具名、参数、结果
db.vector.client.operation向量库查询top_k、相似度阈值、返回文档数

04LangChain4j 核心模块速览

四大核心：AI Services、Chat Memory、RAG Module、Agentic。以"声明式接口 + 注解"为核心编程模型，5 行代码即可跑通。

4.1 AI Services —— 声明式接口（招牌特性）

定义一个接口 + 注解，LangChain4j 用动态代理生成实现，类似 Spring Data JPA / Feign。自动处理 prompt 模板、历史管理、输出解析。这是它"上手快"的根源。

JavaAssistant.java — 最简 AI Service复制
interface Assistant {
    @SystemMessage("你是 Java 技术专家，回答简洁专业。")
    String chat(@UserMessage String userMessage);
}

// 创建：一行代码
ChatModel model = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .build();

Assistant assistant = AiServices.create(Assistant.class, model);
String answer = assistant.chat("解释一下 record 关键字");
Spring Boot / Quarkus 环境下可自动装配 Assistant Bean，无需手动 AiServices.create()，直接注入即可。

4.2 Chat Memory —— 会话记忆

大模型本身无状态，需显式传入历史。LangChain4j 用 ChatMemory 自动管理；MessageWindowChatMemory 滑动窗口控制上下文长度；@MemoryId + ChatMemoryProvider 支持多用户隔离。

JavaMultiUserAssistant.java — 多用户记忆复制
interface MultiUserAssistant {
    String chat(@MemoryId String userId, @UserMessage String message);
}

MultiUserAssistant assistant = AiServices.builder(MultiUserAssistant.class)
        .chatModel(model)
        .chatMemoryProvider(userId ->
            MessageWindowChatMemory.withMaxMessages(10))
        .build();

// 每个 userId 拥有独立记忆窗口
assistant.chat("user-001", "我叫张三");
assistant.chat("user-001", "我叫什么？"); // 记得：张三

4.3 RAG Module —— Easy RAG 与可定制管道

"Easy RAG"是亮点：指向文档即可自动完成 embedding、切分、入库、检索，零配置上手。需要定制时再降级到 ContentRetriever + EmbeddingStoreIngestor。

JavaEasyRag.java — 零配置 RAG复制
// Easy RAG：一行加载文档，自动切分 + embedding + 入库
List<Document> docs = FileSystemDocumentLoader.loadDocuments(
        "docs/handbook.pdf", new TextDocumentParser());

// 自动选择 embedding 模型 + 内存向量库（开箱即用）
EmbeddingStoreIngestor.builder()
        .embeddingStore(embeddingStore)
        .embeddingModel(embeddingModel)
        .build()
        .ingest(docs);

// 注入 ContentRetriever 到 AI Service
Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .contentRetriever(EmbeddingStoreContentRetriever.builder()
                .embeddingStore(embeddingStore)
                .embeddingModel(embeddingModel)
                .maxResults(5)
                .build())
        .build();

4.4 Agentic —— 工具编排与多步推理

LangChain4j 的 Agentic 能力体现在：工具自动调用循环、结构化输出、以及 GoalOrientedPlanner 等规划器驱动的多步推理工作流。适合构建"目标驱动"的 Agent。

JavaAgenticAssistant.java — 工具 + 多步推理复制
interface ResearchAgent {
    @SystemMessage("你是一个研究助手，可调用工具收集信息并汇总。")
    String research(@UserMessage String topic);
}

ResearchAgent agent = AiServices.builder(ResearchAgent.class)
        .chatModel(model)
        .tools(searchTool, calculatorTool, fileWriterTool)
        // 模型自主决定调用哪个工具、调用几次，直至完成任务
        .build();

// 进阶：GoalOrientedPlanner 驱动的多阶段工作流
// planner 拆解目标 → 分步执行 → 循环修正 → 汇总输出
String result = agent.research("对比 2025 年主流向量数据库的延迟与成本");

06选型决策树

面试中被问"你们项目怎么选的"，沿着这棵树走一遍即可。核心逻辑：先看团队站哪、再看模型策略、最后看编排复杂度。

开始 │ ├─ 项目已使用 Spring Boot？ │ ├─ 是 → 主用通义千问且需多智能体 / Graph 编排？ │ │ ├─ 是 → ✦ Spring AI Alibaba（DashScope 官方集成 + Graph 工作流） │ │ └─ 否 → 需要 Spring 配置体系（多环境 / 配置中心）？ │ │ ├─ 是 → ✦ Spring AI（配置驱动，治理友好） │ │ └─ 否 → 需要框架灵活性（AI 层独立演进）？ │ │ ├─ 是 → ✦ LangChain4j（低耦合，可替换） │ │ └─ 否 → ✦ Spring AI（生态一致性优先） │ └─ 否 → 使用 Quarkus / Micronaut？ │ ├─ 是 → ✦ LangChain4j（官方 Quarkus 扩展） │ └─ 否 → 纯 Java / Serverless？ │ └─ 是 → ✦ LangChain4j（无框架依赖，启动快） │ └─ 特殊场景 ├─ 需要 Spring Cloud / Micrometer 原生监控 → ✦ Spring AI ├─ 需要 MCP Server 能力 → ✦ Spring AI 或 LangChain4j（均支持） ├─ 需要跨 Quarkus / Micronaut 兼容 → ✦ LangChain4j ├─ 复杂文档解析（旧 .doc / Notion 等）→ ✦ LangChain4j（加载器更全） ├─ 从 Python LangChain 原型迁移 → ✦ LangChain4j（概念对齐） └─ 快速 PoC / 5 行代码验证 → ✦ LangChain4j（无容器启动）

口述要点：强调"不要把框架选择变成单选题"。大型组织可混用——核心业务服务用 Spring AI 管治理，独立 Agent / PoC 服务用 LangChain4j 保灵活，关键是统一对外 API、日志与评测标准。

07选型五维度详解

这是 Phase 0 验收明确要求掌握的五个维度。每个维度给出两框架的倾向与口述话术。

维度 01

生态成熟度

Spring AI 背靠 Spring 整套生态（Boot / Cloud / Security / Data），API 稳定性与向后兼容有官方保证；LangChain4j 功能覆盖更广（20+ LLM、30+ 向量库），但小版本偶有 breaking change。

Spring AI：稳定成熟LC4j：广度领先
维度 02

企业级支持

Spring AI 由 VMware / Broadcom 商业背书，可观测性（Micrometer）、安全（Spring Security）、配置治理原生集成；LangChain4j 企业级能力需自行补齐监控、限流、审计。

Spring AI：原生强LC4j：需自建
维度 03

社区活跃度

LangChain4j 社区驱动、迭代极快，新模型功能常领先数天上线，GitHub 活跃度高；Spring AI 更新节奏稳健、谨慎，文档与发布更规范。

Spring AI：稳健LC4j：迭代快
维度 04

学习曲线

会 Spring Boot 的人看十分钟文档即可上手 Spring AI；LangChain4j 的 AI Services 声明式接口对任何 Java 开发者都友好，但 Agent / Memory / Tool 等概念需额外理解。

Spring 团队低Java 通用低
维度 05

与 Spring 生态集成度

这是 Spring AI 的主场：配置中心、Actuator、Micrometer、Security 全部原生。LangChain4j 虽有社区 starter，但 ImageModel 等组件未提供自动装配，集成度较浅。

Spring AI：原生深LC4j：社区浅

08面试口述要点与脚本

Phase 0 验收的核心就是"能口述"。下面给出高频题与参考口述脚本，建议对着镜子 / 录音练 3 遍，控制在 2-3 分钟内讲完。

Q1一句话讲清 Spring AI 和 LangChain4j 的区别？
定调句：Spring AI 是"企业集成基础设施层"，LangChain4j 是"灵活 LLM 工具箱"，两者分层互补。

Spring AI 由 Spring 官方出品，走约定优于配置路线，把 AI 能力做成 Spring 一等公民，核心是 ChatClient + Advisor 链，强在可观测性、配置治理和 Spring 生态深度集成；LangChain4j 是社区驱动的 Java 原生库，走声明式接口路线，核心是 AI Services，强在功能广度、跨框架和快速上手。两者不是二选一，企业里可以混用。
Q2Spring AI 的核心 API 有哪些？
五大核心：
① ChatClient —— Fluent API 入口，.prompt().system().user().call()。
② Advisors —— 拦截器链，QuestionAnswerAdvisor 做 RAG、MessageChatMemoryAdvisor 做记忆。
③ Tool Calling —— @Tool 注解注册方法，模型自主回调。
④ MCP —— Model Context Protocol，跨进程工具复用，Client/Server Boot Starter。
⑤ Micrometer 可观测性 —— 原生 Token 用量、耗时指标 + 分布式追踪，这是相对 LangChain4j 的最大优势。
Q3LangChain4j 的核心模块有哪些？
四大核心：
① AI Services —— 招牌特性，接口 + 注解动态代理，类似 Spring Data JPA，5 行代码跑通。
② Chat Memory —— MessageWindowChatMemory 滑动窗口，@MemoryId 多用户隔离。
③ RAG Module —— Easy RAG 零配置上手，ContentRetriever 可定制管道。
④ Agentic —— 工具自动调用循环 + GoalOrientedPlanner 多步推理工作流，适合目标驱动 Agent。
Q4什么场景选 Spring AI？什么场景选 LangChain4j？
选 Spring AI：已有 Spring Boot 微服务体系、需要配置中心/Actuator/Micrometer/Security、长期维护的企业应用、金融医疗等高合规行业。

选 LangChain4j：非 Spring 项目（Quarkus/Micronaut/纯 Java）、快速 PoC 原型、复杂文档解析、从 Python LangChain 迁移、Serverless 追求启动速度。

混用：核心服务用 Spring AI 管治理，独立 Agent 用 LangChain4j 保灵活。
Q5两者在可观测性上的差距具体在哪？
Spring AI 接入 spring-boot-starter-actuator 就自动获得：Token 用量指标（gen_ai.client.token.usage）、模型调用耗时、Advisor 链路 span、向量库查询 span，还能接入 Zipkin/Grafana Tempo 做全链路追踪，HTTP→DB→模型 API 一条 trace 看全。

LangChain4j 虽然加了 ChatModelListener 扩展点，但更像"附加层"，要拿到同等洞察需自己写包装器。生产高合规场景，Spring AI 更稳。
Q6选型时最重要的判断逻辑是什么？
不要问"哪个框架最好"，而要问"哪个让团队少造轮子、少迁移、少背治理债"。

三步走：第一看团队和系统已站在哪（Spring 体系 → Spring AI）；第二看模型策略（多厂商中立两者都行，通义千问优先考虑 Spring AI Alibaba）；第三看编排复杂度（简单调用别过度设计，复杂多 Agent 才上工作流引擎）。生产治理比 Demo 体验更重要。

30 秒电梯版口述（背诵模板）

"Spring AI 和 LangChain4j 是 Java 生态两个主流 AI 框架，分层互补不是二选一。Spring AI 是 Spring 官方的企业集成基础设施层，强在配置治理、Micrometer 可观测性和 Spring 生态深度集成，适合已有 Spring 体系的长期企业项目；LangChain4j 是社区驱动的灵活 LLM 工具箱，核心是声明式 AI Services，上手快、跨框架、功能广，适合快速原型和非 Spring 项目。选型先看团队技术栈——Spring 体系选 Spring AI，非 Spring 或追求灵活选 LangChain4j，大型组织可混用，核心服务管治理、独立服务保灵活。"
