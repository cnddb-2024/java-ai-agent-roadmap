10min阶段一：Advisor 核心概念

Advisors 是 Spring AI 提供的一套拦截器（Interceptor）/ 环绕增强（Around Advice）API，用于在请求发送给大语言模型（LLM）之前、以及响应返回给调用方之后，对数据进行拦截、修改与增强。它的设计思想与 Spring AOP 高度一致——这正是 Phase 0 强调的"双框架认知"：把你已掌握的 Spring 拦截器/过滤器经验迁移到 AI 调用链上。

1.1 解决什么问题

  • 封装重复的 GenAI 模式：日志、记忆、RAG、敏感词等横切逻辑可复用。
  • 数据转换：在 Prompt 进入模型前注入上下文，在 ChatResponse 返回后格式化结果。
  • 可移植性：同一套 Advisor 可跨不同 ChatModel 与用例复用。

1.2 核心组件

  • Advisor：顶层接口，定义 getName() 与 getOrder()。
  • CallAroundAdvisor：非流式（同步）场景的环绕增强接口，核心方法为 aroundCall()（旧版本为 nextAroundCall()）。
  • StreamAroundAdvisor：流式（响应式）场景对应接口。
  • AdvisedRequest：未密封的 Prompt 请求载体，可在链中被修改。
  • AdvisedResponse：Chat Completion 响应载体，携带共享的 advise-context。
  • CallAroundAdvisorChain：负责按顺序串联并调用多个 Advisor。
执行顺序（堆栈语义）：Advisor 按 getOrder() 升序排列，值越小越先处理请求；响应则以相反顺序回溯。设置为 Ordered.HIGHEST_PRECEDENCE 的 Advisor 最先处理请求、最后处理响应，与 Servlet Filter / Spring Interceptor 的"先进后出"完全一致。

1.3 请求流转过程

  1. 框架从用户 Prompt 创建 AdvisedRequest，并附带空的 advisor-context。
  2. 链中每个 Advisor 处理（并可能修改）请求，然后调用下一个 Advisor；也可选择"阻断"——不调用下一个节点，此时由当前 Advisor 负责填充响应或抛出异常。
  3. 框架自动追加的最后一个 Advisor 把请求真正发送给 Chat Model。
  4. 模型响应沿链反向回传，被包装成 AdvisedResponse。
  5. 每个 Advisor 可在回程处理/修改响应，最终提取出 ChatResponse 返回给客户端。

15min阶段二：CallAroundAdvisor 实现

下面实现两个最常用的自定义 Advisor：日志 Advisor（记录请求与响应耗时）和 Token 计数 Advisor（粗略统计字符/token 用量并写入上下文）。它们都实现 CallAroundAdvisor 接口。

2.1 自定义日志 Advisor

package com.example.advisor;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.chat.client.AdvisedRequest;
import org.springframework.ai.chat.client.AdvisedResponse;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisor;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisorChain;
import org.springframework.core.Ordered;

public class LoggingAdvisor implements CallAroundAdvisor {

    private static final Logger log = LoggerFactory.getLogger(LoggingAdvisor.class);

    @Override
    public String getName() {
        return "LoggingAdvisor";
    }

    @Override
    public int getOrder() {
        // 越小越先执行，这里放在最外层
        return Ordered.HIGHEST_PRECEDENCE;
    }

    @Override
    public AdvisedResponse aroundCall(AdvisedRequest request, CallAroundAdvisorChain chain) {
        long start = System.currentTimeMillis();
        String userText = request.userText();

        log.info("[AI-REQ] model={}, userText={}",
                request.chatModel() != null ? request.chatModel().getClass().getSimpleName() : "default",
                userText);

        // 必须调用 chain.nextAroundCall 把请求继续向后传递
        AdvisedResponse response = chain.nextAroundCall(request);

        long cost = System.currentTimeMillis() - start;
        String content = response.response() != null && response.response().getResult() != null
                ? response.response().getResult().getOutput().getText()
                : "";
        log.info("[AI-RESP] cost={}ms, content={}", cost, content);

        return response;
    }
}

2.2 Token 计数 Advisor

该 Advisor 在请求前把字符数作为粗略 token 估算写入 advise-context，在响应后累加输出长度，便于上层观测。

package com.example.advisor;

import java.util.Map;
import org.springframework.ai.chat.client.AdvisedRequest;
import org.springframework.ai.chat.client.AdvisedResponse;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisor;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisorChain;
import org.springframework.core.Ordered;

public class TokenCountAdvisor implements CallAroundAdvisor {

    public static final String CTX_INPUT_TOKENS = "estimated_input_tokens";
    public static final String CTX_OUTPUT_TOKENS = "estimated_output_tokens";

    // 粗略估算：1 token 约等于 4 个英文字符；中文场景可按字符数近似
    private static final double CHARS_PER_TOKEN = 4.0;

    @Override
    public String getName() {
        return "TokenCountAdvisor";
    }

    @Override
    public int getOrder() {
        return Ordered.HIGHEST_PRECEDENCE + 10;
    }

    @Override
    public AdvisedResponse aroundCall(AdvisedRequest request, CallAroundAdvisorChain chain) {
        int inputTokens = (int) Math.ceil(request.userText().length() / CHARS_PER_TOKEN);

        // 通过 adviseContext 向下游传递状态
        AdvisedRequest mutated = AdvisedRequest.from(request)
                .withAdviseContext(Map.of(CTX_INPUT_TOKENS, inputTokens))
                .build();

        AdvisedResponse response = chain.nextAroundCall(mutated);

        String output = response.response().getResult().getOutput().getText();
        int outputTokens = (int) Math.ceil(output.length() / CHARS_PER_TOKEN);

        // 响应回程时把统计信息合并回 context
        response.adviseContext().put(CTX_OUTPUT_TOKENS, outputTokens);
        return response;
    }
}
要点：务必调用 chain.nextAroundCall(...)，否则请求会被阻断。需要修改请求时使用 AdvisedRequest.from(request) 构建器；共享状态通过 adviseContext() 这个 Map 在整条链中传递。

15min阶段三：链式编排多 Advisor

多个 Advisor 通过 getOrder() 决定顺序。下面再加一个敏感词拦截 Advisor——它在命中敏感词时不调用下一个节点，直接构造一个拒绝响应（即"阻断请求"），这与 SafeGuardAdvisor 的思路一致。然后把三个 Advisor 注册到 ChatClient。

3.1 敏感词拦截 Advisor

package com.example.advisor;

import java.util.List;
import java.util.Set;
import org.springframework.ai.chat.client.AdvisedRequest;
import org.springframework.ai.chat.client.AdvisedResponse;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisor;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisorChain;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.core.Ordered;

public class SensitiveWordAdvisor implements CallAroundAdvisor {

    private final Set<String> blockedWords;

    public SensitiveWordAdvisor(Set<String> blockedWords) {
        this.blockedWords = blockedWords;
    }

    @Override
    public String getName() {
        return "SensitiveWordAdvisor";
    }

    @Override
    public int getOrder() {
        // 最先做安全校验，放在日志之后、业务之前
        return Ordered.HIGHEST_PRECEDENCE + 5;
    }

    @Override
    public AdvisedResponse aroundCall(AdvisedRequest request, CallAroundAdvisorChain chain) {
        String userText = request.userText();

        for (String word : blockedWords) {
            if (userText.contains(word)) {
                // 命中敏感词：阻断请求，不调用 chain.nextAroundCall
                AssistantMessage answer = new AssistantMessage("您的提问包含被禁止的词汇，已被拦截。");
                ChatResponse chatResponse = new ChatResponse(List.of(new Generation(answer)));
                return new AdvisedResponse(chatResponse, request.adviseContext());
            }
        }
        return chain.nextAroundCall(request);
    }
}

3.2 注册并编排多个 Advisor

推荐在构建期通过 defaultAdvisors() 注册，顺序最终由各 Advisor 的 getOrder() 决定，而非添加顺序。

package com.example.config;

import java.util.Set;
import com.example.advisor.LoggingAdvisor;
import com.example.advisor.SensitiveWordAdvisor;
import com.example.advisor.TokenCountAdvisor;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatModel chatModel) {
        SensitiveWordAdvisor guard = new SensitiveWordAdvisor(
                Set.of("违禁词A", "违禁词B", "违法内容"));

        return ChatClient.builder(chatModel)
                .defaultAdvisors(
                        new LoggingAdvisor(),      // order = MIN_VALUE
                        guard,                    // order = MIN_VALUE + 5
                        new TokenCountAdvisor()   // order = MIN_VALUE + 10
                )
                .build();
    }
}

3.3 运行时按请求动态传参

可以在单次调用时通过 .advisors(spec -> spec.param(...)) 传入会话级参数（例如对话 ID、过滤表达式等）。

String answer = chatClient.prompt()
        .user("请介绍一下 Spring AI 的 Advisor 机制")
        .advisors(spec -> spec
                .param("chat_memory_conversation_id", "conv-001")
                .param("chat_memory_response_size", 50))
        .call()
        .content();

System.out.println(answer);
双框架对照：这套"请求前环绕 → 放行 chain → 响应后环绕 → 可阻断短路"的模型，就是 Spring MVC HandlerInterceptor 与 Servlet Filter 在 AI 领域的翻版。理解了拦截器栈，就理解了 Advisor 链。

15min阶段四：QuestionAnswerAdvisor 知识库增强（RAG）

Spring AI 内置了 QuestionAnswerAdvisor，它封装了完整的 RAG 流程：用用户问题去向量库做相似度检索，把命中文档拼接到 Prompt 中作为上下文，再交给 LLM 回答。

4.1 数据加载（ETL）

先把文档切分并写入 VectorStore。下面演示用内存向量库做最小可运行示例。

package com.example.rag;

import java.util.List;
import org.springframework.ai.document.Document;
import org.springframework.ai.reader.TextDocumentReader;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.core.io.Resource;
import org.springframework.stereotype.Component;

@Component
public class IngestionService {

    private final VectorStore vectorStore;

    public IngestionService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void ingest(Resource knowledgeFile) {
        // 1. 读取
        List<Document> raw = new TextDocumentReader(knowledgeFile).get();
        // 2. 切分
        List<Document> chunks = new TokenTextSplitter().apply(raw);
        // 3. 写入向量库（Embedding 由 VectorStore 自动调用）
        vectorStore.add(chunks);
    }
}

4.2 接入 QuestionAnswerAdvisor

使用 builder 配置相似度阈值与 topK，并注册到 ChatClient。

package com.example.config;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.vectorstore.QuestionAnswerAdvisor;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class RagChatClientConfig {

    @Bean
    public ChatClient ragChatClient(ChatModel chatModel, VectorStore vectorStore) {
        QuestionAnswerAdvisor qaAdvisor = QuestionAnswerAdvisor.builder(vectorStore)
                .searchRequest(SearchRequest.builder()
                        .similarityThreshold(0.8d)
                        .topK(6)
                        .build())
                .build();

        return ChatClient.builder(chatModel)
                .defaultAdvisors(qaAdvisor)
                .build();
    }
}

Phase 0 验收对照：双框架认知

本任务是 Phase 0"定向与双框架地基"的组成部分，验收点对应如下：

  • Spring 侧地基：能说清 Advisor 与 Spring AOP / HandlerInterceptor / Servlet Filter 在"环绕增强 + 责任链 + 可短路"上的同源关系。
  • Spring AI 侧地基：掌握 ChatClient + ChatModel + Advisor + VectorStore 四件套的协作方式，理解 AdvisedRequest/AdvisedResponse/advise-context 三件套。
  • 可观测性意识：Advisor 自动接入 Micrometer/Tracing，日志/Token Advisor 是落地可观测性的天然切入点。
  • 横切能力闭环：日志、安全（敏感词拦截）、记忆（ChatMemoryAdvisor）、知识增强（QuestionAnswerAdvisor）四类典型 Advisor 均能识别并独立实现/装配。

关联面试题：Spring AI 核心机制（第二梯队）

  1. Advisor 的执行顺序如何控制？为什么说它是"堆栈"语义？
    答：通过 getOrder() 升序处理请求、逆序处理响应，值越小越靠近外层（类似 Ordered.HIGHEST_PRECEDENCE）。这与 Filter 链的先进后出一致。
  2. 如何在 Advisor 中"阻断"一次模型调用？
    答：不调用 chain.nextAroundCall()，直接构造 AdvisedResponse 返回或抛出异常（参考 SafeGuardAdvisor / 本教程的 SensitiveWordAdvisor）。
  3. AdvisedRequest 与 Prompt 的区别？advise-context 有什么用？
    答：AdvisedRequest 是未密封、可在链中修改的请求载体；advise-context 是贯穿整条链的共享 Map，用于在多个 Advisor 间传递状态（如 token 计数、会话 ID、过滤表达式）。
  4. QuestionAnswerAdvisor 内部做了什么？如何自定义检索阈值与过滤条件？
    答：它用用户问题做向量相似度检索，把 topK 文档拼入 Prompt 上下文再交给 LLM；可通过 SearchRequest.similarityThreshold()/topK() 配置，运行时用 FILTER_EXPRESSION 参数动态过滤。
  5. CallAroundAdvisor 与 StreamAroundAdvisor 的区别？
    答：前者用于同步阻塞的 call()，后者用于响应式流式的 stream()；需要同时支持两种调用时可分别实现两个接口。
