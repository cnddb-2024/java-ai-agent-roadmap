# Spring AI 教程产出原则：开箱优先 + 全量镜像

- 版本：2026-10-17
- 来源：springai2-demo 迁移实战复盘（T1–T4），用户强制确立
- 效力：对一切 Spring AI 学习教程、迁移文档、示例代码的产出有强制约束力

---

## 原则一：开箱优先（Official-First）

**陈述**：任何 Spring AI 能力，动手自研前必须先证明"官方没有开箱实现"。

**执行步骤（顺序强制）**：

1. 查**当前所用版本**：本地官方文档镜像 + jar 实证（javap 反编译、`META-INF/spring-configuration-metadata.json` 查配置键）
2. 查**更高已发布版本**：以 GA 版本为基线；M 里程碑（如 2.1.0-M1）仅作路线参考，不作为采用依据
3. 判定"有开箱" → 必须先学习并采用官方实现，**禁止跳过开箱直接手写**
4. 判定"无开箱" → 才允许自研，且必须标注：自研范围、对标对象、待官方实现后替换的计划

**立项三问（缺一不可，写入任务/教程开头）**：

1. 当前版本有什么？
2. 更高已发布 GA 版本有什么？
3. 为什么不用更高版本（M 版不算）？

**真实反例（2026-10-17 复盘）**：token 预算记忆 advisor 立项时断言"2.0.1 没有、2.1 有"。jar 实证修正：① `TokenCountEstimator` 接口 + `JTokkitTokenCountEstimator` 实现在 2.0.1 的 spring-ai-commons **已存在**（当时只扫了 spring-ai-model 一个 jar，漏了 commons）；② 2.1.0 尚未 GA（仅 2.1.0-M1 里程碑），token 预算属于**计划中**能力。若立项时执行本原则，两处错误都不会发生。

---

## 原则二：全量镜像（Full-Mirror）

**陈述**：官方文档按任务最小化抓取 = 制造认知盲区；必须全量镜像。

**执行步骤**：

1. 全量抓取 `docs.spring.io/spring-ai/reference` 到本地镜像目录（如 `docs/springai-official/`）：每页一个 `.md` + `_manifest.txt`（URL 来源清单），对齐当前所用版本
2. 任务动手前先在镜像目录定位相关章节：镜像有 → 直接引用；镜像缺 → **先补抓该页再下断言**
3. spring-ai 版本升级后：重抓全套镜像，`_manifest.txt` 即版本对齐凭证

**现有可复用资产（同机时）**：`F:\code\springai2-demo\docs\springai-official\`（112 页全量镜像 + `_manifest.txt`，2026-10-17 抓取，对齐 2.0.1）。同机会话可直接引用或复制，无需重抓。

**断言验证链（三级，效力递增）**：

1. **本地镜像** —— 第一道，最快
2. **官网抓取** —— 镜像缺页或疑似版本漂移时
3. **jar 实证** —— javap 解包 `~/.m2` 的 spring-ai jar；配置键以 `META-INF/spring-configuration-metadata.json` 为准；**文档与 jar 冲突时，以 jar 为准**

**禁止事项**：

- 禁止从未审查到的代码路径推断全局行为
- 禁止凭训练记忆断言版本特定行为（AI 训练知识存在版本错位，如混入 1.x 时代印象）
- 禁止把"文档没写"当"功能不存在"（真实案例：2.0.1 的 `LastMaxTokenSizeContentPurger` 存在于 jar 却未写入官方文档）

## 产出前自检清单

- [ ] 涉及的能力查过官方开箱实现吗？（当前版本：镜像 + jar 双证）
- [ ] 更高已发布 GA 版本有对应能力吗？立项三问写了吗？
- [ ] 所有框架行为断言都过了三级验证链吗？（镜像 → 官网 → jar）
- [ ] 引用的配置键在 `spring-configuration-metadata.json` 里实证过吗？
- [ ] 自研实现标注了自研范围 + 对标对象 + 替换计划吗？
