2Function Calling 底层原理10 min

Function Calling（又称 Tool Use）并不是让模型"真的执行函数"，而是让模型在需要外部信息或动作时， 以结构化 JSON 输出"我想调用哪个函数、参数是什么"。真正的函数执行由应用侧（Java 框架）完成， 再把结果作为一条特殊消息塞回对话，由模型完成最终自然语言回答。

2.1 完整生命周期（四次握手）

┌──────────┐   ① user message + tools(JSON Schema)   ┌──────────┐
│  Client  │ ───────────────────────────────────────▶ │   LLM    │
│ (Java)   │ ◀─────────────────────────────────────── │          │
└──────────┘     ② assistant: tool_calls=[{...}]      └────┬─────┘
      ▲                                                    │
      │ ③ 框架反射执行本地函数，组装 tool message           │
      │                                                    ▼
┌──────────┐   ④ 回传 tool message（含结果）          ┌──────────┐
│  Local   │ ───────────────────────────────────────▶ │   LLM    │
│ Function │ ◀─────────────────────────────────────── │          │
└──────────┘     ⑤ assistant: 最终自然语言回答        └──────────┘

2.2 协议视角：一条消息的来回

以 OpenAI Chat Completions 协议为例，关键在于三类字段：

阶段字段作用
请求tools告诉模型"你可以用哪些函数"，每个函数用 JSON Schema 描述。
请求tool_choice控制模型是否/如何选择工具（none / auto / required / 指定函数）。
响应①finish_reason="tool_calls"模型决定调用工具，content 通常为 null。
响应①tool_calls[].function包含 name 与 arguments（JSON 字符串）。
请求②messages 追加 role:"tool"把函数执行结果回传，tool_call_id 必须一一对应。
响应②content模型基于工具结果生成最终自然语言回答。

2.3 一次真实的 wire 交互（节选）

// ① 上行：声明工具
{
  "model": "gpt-4o-mini",
  "messages": [{"role":"user", "content":"北京今天天气怎么样？"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "getWeather",
      "description": "查询指定城市的实时天气",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type":"string", "description":"城市名，如 Beijing"}
        },
        "required": ["city"]
      }
    }
  }],
  "tool_choice": "auto"
}

// ② 下行：模型决定调用
{
  "finish_reason": "tool_calls",
  "message": {
    "role": "assistant",
    "tool_calls": [{
      "id": "call_abc123",
      "type": "function",
      "function": {"name":"getWeather", "arguments":"{\"city\":\"Beijing\"}"}
    }]
  }
}

// ③ 上行：回传结果（Java 侧执行后）
{
  "role": "tool",
  "tool_call_id": "call_abc123",
  "content": "{\"temp\":27,\"condition\":\"晴\"}"
}

// ④ 下行：最终回答
{ "role":"assistant", "content":"北京今天晴，气温约 27℃，适合外出。" }

关键点：模型本身不联网、不执行代码。它只负责"决定调用 + 填参数"以及"看见结果后组织语言"。 真正的副作用（HTTP 请求、查 DB、发消息）发生在 Java 进程里。

2.4 MCP vs Function Call（第一梯队面试题）

维度Function CallingMCP (Model Context Protocol)
本质模型厂商在 Chat API 中定义的"工具调用"消息结构一个开放的客户端-服务端协议（stdio / HTTP+SSE），标准化"工具/资源/Prompt"暴露方式
耦合与具体模型/SDK 强绑定（OpenAI、Gemini、Anthropic 字段不同）跨模型、跨客户端可复用；一次实现，多个 MCP Client 可接入
发现启动时硬编码 tools 列表塞进请求运行时 tools/list 动态发现，支持热插拔
执行方应用进程内反射调用本地方法可调用本地/远程 MCP Server 暴露的工具，天然跨进程、跨语言
关系MCP 是"传输与发现层"；底层最终仍会被 MCP Client 翻译成各家模型的 Function Calling 消息。两者不是替代，而是分层。

3tool_choice 三种模式5 min

tool_choice 是你给模型的"工具使用策略开关"，Spring AI / LangChain4j 都做了对应封装。

取值语义典型场景
none 禁用工具。即便传了 tools，模型也不会调用，直接作答。 纯闲聊、敏感任务兜底、A/B 对比。
auto
(默认)		 模型自行决定：是直接回答，还是调用一个或多个工具。 通用 Agent、用户意图不确定时。
required 必须调用至少一个工具。模型被强制走工具路径。 结构化抽取、强约束工作流（"必须查库后才能回答"）。
{"type":"function","function":{"name":"xxx"}} 强制调用指定函数。 流水线中固定节点，如"必须先调 getWeather"。

在框架里怎么写

// Spring AI（1.0 M+/GA）
ChatResponse resp = chatClient.prompt()
    .user("北京天气？")
    .tools(weatherTools)
    .options(OpenAiChatOptions.builder()
        .toolChoice(ToolChoice.AUTO)   // NONE / REQUIRED / FUNCTION
        .build())
    .call()
    .chatResponse();

// LangChain4j
OpenAiChatModel model = OpenAiChatModel.builder()
    .apiKey(System.getenv("OPENAI_API_KEY"))
    .toolChoice(ToolChoice.AUTO)  // 也可在 @Tool 级或 AiService 级覆盖
    .build();

注意：required 只保证"至少调一次工具"，并不保证调用正确的工具。 工具的 description 仍然决定模型能否选对。

4JSON Schema 与工具定义8 min

一个工具能被模型正确使用，本质上取决于它的"自描述"够不够清楚。 底层就是一段 JSON Schema，Spring AI / LangChain4j 会在启动时通过反射把你的方法签名 + 注解翻译成它。

4.1 一个工具定义应包含什么

  • name：函数名。短、snake_case 或 camelCase，语义清晰（get_weather 优于 func1）。
  • description：一句话说明"什么时候用"。这是模型选工具的主要依据，写得差就会选错。
  • parameters：JSON Schema，描述参数类型、必填项、枚举、嵌套对象。
  • 每个参数的 description：说明取值范围、单位、示例（如"温度单位，celsius/fahrenheit"）。
  • 返回值（可选但推荐）：部分实现会使用返回值的 schema/描述，帮助模型理解结果结构。

4.2 手工写一份：天气 + 时间

[
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询给定城市的当前天气；当用户询问天气/气温/是否下雨时使用。",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {
            "type": "string",
            "description": "城市中文名或英文名，例如 'Beijing'、'上海'"
          },
          "unit": {
            "type": "string",
            "enum": ["celsius", "fahrenheit"],
            "default": "celsius",
            "description": "温度单位"
          }
        },
        "required": ["city"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "current_time",
      "description": "返回指定时区的当前日期与时间。当用户问'现在几点/今天几号'时使用。",
      "parameters": {
        "type": "object",
        "properties": {
          "timezone": {
            "type": "string",
            "description": "IANA 时区，例如 Asia/Shanghai、UTC",
            "default": "Asia/Shanghai"
          }
        }
      }
    }
  }
]

4.3 写好描述的 5 条军规

  1. 说清"何时用"，而不只是"做什么"——模型是按"语义匹配"选工具的。
  2. 参数给示例值，尤其是枚举、日期、ID 格式。
  3. 单位写进描述（℃/℉、元/美元、秒/毫秒）。
  4. 避免两个工具描述高度重叠，否则模型会随机选。
  5. 返回结构稳定：用 JSON 对象而非裸字符串，便于模型稳定解析。

5Spring AI 实战15 min

Spring AI 提供两条风格不同的工具接入路径： 声明式 @Tool（最常用，反射 + 注解驱动）和 编程式 FunctionCallback（需要动态生成工具或精细控制时使用）。 下面用同一个"天气 + 时间"场景演示两种方式。

5.1 依赖（Maven）

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-starter-model-openai</artifactId>
</dependency>

5.2 方式一：@Tool 注解声明式

package com.example.agent.tools;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;
import java.time.*;
import java.util.Map;

@Component
public class WeatherTools {

    @Tool(name = "get_weather",
          description = "查询给定城市的当前天气；当用户询问天气/气温/是否下雨时使用。")
    public Map<String, Object> getWeather(
            @ToolParam(description = "城市名，例如 Beijing 或 上海") String city,
            @ToolParam(description = "温度单位：celsius 或 fahrenheit", required = false) String unit) {

        String u = (unit == null) ? "celsius" : unit;
        // 真实项目里这里替换成 RestClient/WebClient 调用气象 API
        return Map.of(
            "city", city,
            "temperature", "celsius".equals(u) ? 27 : 80,
            "unit", u,
            "condition", "晴"
        );
    }

    @Tool(name = "current_time",
          description = "返回指定时区的当前日期与时间；当用户问'现在几点/今天几号'时使用。")
    public String currentTime(
            @ToolParam(description = "IANA 时区，例如 Asia/Shanghai", required = false) String timezone) {
        ZoneId zone = (timezone == null)
            ? ZoneId.of("Asia/Shanghai")
            : ZoneId.of(timezone);
        return ZonedDateTime.now(zone).toString();
    }
}

在 ChatClient 中挂载工具

package com.example.agent;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.ai.openai.api.tool.*;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.stereotype.Service;

@Service
public class AgentService {

    private final ChatClient chatClient;
    private final WeatherTools weatherTools;

    public AgentService(ChatClient.Builder builder, WeatherTools weatherTools) {
        this.chatClient = builder.build();
        this.weatherTools = weatherTools;
    }

    public String chat(String userInput) {
        return chatClient.prompt()
                .user(userInput)
                .tools(weatherTools)               // ← 关键：注册 @Tool 方法
                .call()
                .content();
    }
}

小贴士：.tools(...) 接受任意对象，Spring AI 会扫描其 @Tool 方法并生成 JSON Schema。 一个类里可以放多个 @Tool；多个 Bean 也可同时传入。

5.3 方式二：FunctionCallback 编程式

当工具定义需要在运行时动态生成（比如从数据库读取可用函数列表）， 或者你需要完全掌控参数解析与结果序列化，可以使用 FunctionCallback。 

package com.example.agent.tools;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.ai.tool.function.FunctionToolCallback;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import java.time.*;
import java.util.Map;

@Configuration
public class ToolConfig {

    private final ObjectMapper json = new ObjectMapper();

    @Bean
    public FunctionToolCallback weatherCallback() {
        return FunctionToolCallback.builder("get_weather", this::invokeWeather)
                .description("查询给定城市的当前天气；当用户询问天气/气温/是否下雨时使用。")
                .inputSchema("""
                    {
                      "type":"object",
                      "properties":{
                        "city":{"type":"string","description":"城市名，如 Beijing"},
                        "unit":{"type":"string","enum":["celsius","fahrenheit"]}
                      },
                      "required":["city"]
                    }
                    """)
                .build();
    }

    private String invokeWeather(String jsonInput) {
        try {
            JsonNode node = json.readTree(jsonInput);
            String city = node.path("city").asText("Beijing");
            String unit = node.path("unit").asText("celsius");
            Map<String, Object> result = Map.of(
                "city", city,
                "temperature", "celsius".equals(unit) ? 27 : 80,
                "condition", "晴"
            );
            return json.writeValueAsString(result);
        } catch (Exception e) {
            return "{\"error\":\"" + e.getMessage() + "\"}";
        }
    }

    @Bean
    public FunctionToolCallback timeCallback() {
        return FunctionToolCallback.builder("current_time", input ->
                ZonedDateTime.now(ZoneId.of("Asia/Shanghai")).toString())
            .description("返回 Asia/Shanghai 当前时间；当用户问'现在几点'时使用。")
            .inputType(String.class) // 无参也可声明
            .build();
    }
}

挂载编程式回调

public String chatWithCallbacks(String input) {
    return chatClient.prompt()
        .user(input)
        .toolCallbacks(weatherCallback, timeCallback)  // ← FunctionCallback 路径
        .call()
        .content();
}

6.3 定义 AiService 接口并装配工具

package com.example.l4j;

import dev.langchain4j.service.SystemMessage;
import dev.langchain4j.service.UserMessage;
import dev.langchain4j.service.spring.AiService;

@AiService
interface Assistant {

    @SystemMessage("你是一个简洁的中文助手，需要时调用工具，不要编造数据。")
    String chat(@UserMessage String message);
}

若不用 Spring Boot 自动装配，可以用原生 builder（也是题目要求的方式）：

package com.example.l4j;

import dev.langchain4j.memory.chat.MessageWindowChatMemory;
import dev.langchain4j.model.openai.OpenAiChatModel;
import dev.langchain4j.service.AiServices;

public class AssistantApp {

    public static void main(String[] args) {
        OpenAiChatModel model = OpenAiChatModel.builder()
            .apiKey(System.getenv("OPENAI_API_KEY"))
            .modelName("gpt-4o-mini")
            .temperature(0.2)
            .build();

        WeatherTools tools = new WeatherTools();

        Assistant assistant = AiServices.builder(Assistant.class)
            .chatLanguageModel(model)
            .tools(tools)                           // ← 关键：把 @Tool 方法暴露给模型
            .chatMemory(MessageWindowChatMemory.withMaxMessages(20))
            .build();

        String answer = assistant.chat("上海天气怎样？现在几点？");
        System.out.println(answer);
    }
}

6.4 细粒度：ToolSpecification 编程式（可选）

与 Spring AI 的 FunctionCallback 对应，LangChain4j 也可以用 ToolSpecification + ToolExecutor 在运行时动态拼装工具，适合从数据库/配置中心加载工具清单。 

var spec = dev.langchain4j.agent.tool.ToolSpecification.builder()
    .name("get_weather")
    .description("查询城市天气")
    .parameters(JsonObjectUtils.from("""
        {"type":"object",
         "properties":{"city":{"type":"string"}},
         "required":["city"]}
        """))
    .build();
// 然后在低层 ChatModel 层配合 ToolExecutor 使用；AiServices 路径下一般用不到。

7常见坑与排查5 min

坑 1：参数描述不清 → 模型乱填或漏填

现象：city 被填成 "中国"；日期填成 "明天" 而非 ISO 格式。

解法：在 @ToolParam/@P 描述里写枚举、示例、单位、格式。必要时用 enum 强约束。

坑 2：工具循环（tool loop）

现象：A 工具的结果让模型再次调用 A，无限往返直到 token 超限。

解法：在 system message 明确"同一参数不要重复调用"；设置最大工具轮数；对结果做缓存/幂等。

坑 3：超时与重试

现象：下游气象 API 偶发慢，模型等到 read timeout，整轮失败。

解法：工具方法内部加超时 + 熔断（Resilience4j）；对幂等查询开启有限重试；把错误信息以 JSON 返回给模型，让它决定如何告知用户，而不是直接抛异常。

坑 4：非幂等工具被重复执行

现象：模型在一次请求里重复发起 create_order，或重试导致双写。

解法：写操作必须带 idempotency_key；服务端去重；尽量把"读"和"写"工具分开命名。

坑 5：工具结果过大 / 非结构化

现象：把整个 HTML/日志塞进 content，token 爆炸。

解法：工具返回精炼 JSON；对长文本先做摘要或分页；只返回模型决策所需字段。

坑 6：并行工具调用顺序问题

现象：模型在一条消息里返回多个 tool_calls，框架并行执行，但其中一个依赖另一个的结果。

解法：让模型分轮调用；或在工具描述里明确"需先调用 X"；必要时用 required + 指定函数串联工作流。

排查 Checklist

  1. 打印完整的 messages 数组，看 tool_calls 与 role:"tool" 的 tool_call_id 是否对齐。
  2. 打开框架的 wire logging（Spring AI: logging.level.org.springframework.ai=DEBUG；LangChain4j: .logRequests(true).logResponses(true)）。
  3. 检查工具 description 是否与用户意图字面重合，避免两个工具描述过近。
  4. 确认 JSON Schema 的 required、enum、default 是否符合预期。
  5. 对写操作验证幂等键、事务边界和异常回传。

面试题回扣："请描述一次 Function Call 的完整生命周期"——按本教程第 2 节的四次握手讲， 并补充"模型不执行、框架反射、tool_call_id 必须对齐、MCP 是发现/传输层而非替代 Function Call"，基本覆盖第一梯队考点。
