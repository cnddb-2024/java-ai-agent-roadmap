Spring AI vs LangChain4j
选型对比笔记与口述练习

Java AI Agent 学习路线图 · 验收项 · 面试第一梯队："Spring AI vs LangChain4j 选型"

总预估时长 约 50 分钟 主线语言 Java 形式 笔记 + 口述

完成本教程后，你应当能够：

  • 在 Chat、Tool Calling、RAG、Memory、可观测性、向量库、MCP 七个维度做出对位比较。
  • 读懂并独立写出两个框架最小可用的 Chat 与 Tool Calling 示例。
  • 面对一个新项目需求，能通过决策树在 2 分钟内给出选型建议并说明理由。
  • 脱稿回答 5 个面试高频问题，覆盖定位、差异、选型、生态与踩坑。

二、架构哲学对比 10 min

两个框架解决的是同一类问题——"把 LLM 接入 JVM 应用"，但走了两条几乎相反的路。理解哲学差异，比记住 API 更重要，因为 API 会变，哲学不会。

Spring AI

声明式 · Spring 原生 · 约定优于配置
  • 由 Spring 官方团队主导，天然融入 spring-boot 生态。
  • 核心抽象 ChatClient、ChatModel、Advisors，通过 @Bean + application.yml 装配。
  • 提供 Starter（spring-ai-openai-spring-boot-starter 等），自动装配一切。
  • RAG 走"Advisor 拦截器链"，像 Spring Security / MVC Interceptor 一样可组合。
  • 可观测性直接对接 Micrometer / Observation API，零额外配置。
  • 强项：企业级 Spring Boot 项目的开箱即用与一致体验。

LangChain4j

工具箱式 · 框架无关 · 显式组装
  • 社区驱动，灵感来自 Python LangChain，但针对 Java 做了重写与裁剪。
  • 核心抽象 ChatLanguageModel、AiServices、ContentRetriever，通过 Builder 显式拼装。
  • 不绑定 Spring，可在 Quarkus、Micronaut、普通 main 方法、Android 中使用。
  • 提供 langchain4j-spring-boot-starter 作为集成之一，但非必需。
  • RAG 由一组可替换组件（EmbeddingStore / Retriever / Reranker）组合，颗粒度更细。
  • 强项：模型/组件覆盖最广、可嵌入任意 Java 运行时、AI Service 声明式接口体验极佳。

一句话差异

Spring AI = "Spring 团队替你选好默认值，你写业务"；LangChain4j = "给你一箱子零件，你自己拼，但零件最多最全"。

三、核心能力对比表 15 min

下表从七个工程维度对位比较。注意"谁更好"高度依赖场景，这里只标注客观差异。

能力维度 Spring AI LangChain4j
Chat / 对话抽象 ChatClient（Fluent API）+ ChatModel，支持 Prompt 模板、结构化输出 BeanOutputConverter。 ChatLanguageModel + AiServices，可用普通 Java interface 声明对话，自动代理实现。
Tool Calling
（函数调用）		 方法标注 @Tool（含 description），通过 .tools(bean) 注册；参数 schema 自动推导。 方法标注 @Tool，或用 @Bean 暴露 AI Service；工具发现支持 classpath 扫描与显式注册。
RAG 架构 基于 Advisors 拦截器链（QuestionAnswerAdvisor、RetrievalAugmentationAdvisor），与 Spring 生态风格一致。 高度模块化：EmbeddingStore + ContentRetriever + Reranker + RetrievalAugmentor，可按需替换每一环。
Memory / 记忆 ChatMemory 接口 + InMemoryChatMemoryRepository / JDBC / Cassandra 等实现，通过 MessageChatMemoryAdvisor 注入。 ChatMemory 接口 + 多种窗口/Token 策略（MessageWindowChatMemory、TokenWindowChatMemory），可按 user/messageId 隔离。
可观测性 原生 Micrometer Observation，自动产生 spans/metrics，对接 Zipkin/Jaeger/Prometheus 几乎零配置。 提供 ChatModelListener 机制与 Spring Boot 集成下的 Micrometer 支持，但需更多手动配置。
向量库支持 覆盖主流：PGVector、Redis、Milvus、Chroma、Elasticsearch、Weaviate、Qdrant、OpenSearch 等 20+。 数量最多：30+ EmbeddingStore 实现，含 Infinispan、Neo4j、Vespa、Typesense、Azure AI Search 等长尾选项。
MCP 支持 官方 spring-ai-mcp 模块，同时支持 MCP Client / Server，基于 WebFlux / WebMVC，与 Spring Boot 深度集成。 提供 langchain4j-mcp 模块，支持 MCP client 通过 stdio / HTTP/SSE 接入工具，框架无关。

四、代码对比示例 10 min

下面给出两组最小可运行示例：普通 Chat 与 Tool Calling。请边看边在脑中口述"这一步在做什么、为什么这么写"。

4.1 Spring AI

// 依赖（pom.xml 关键 starter）

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

// application.yml

spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o-mini
          temperature: 0.3

// 简单 Chat

@RestController
class ChatController {

    private final ChatClient chatClient;

    ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)
                .call()
                .content();
    }
}

// Tool Calling：用 @Tool 暴露一个查天气方法

@Component
class WeatherTools {

    @Tool(description = "根据城市名查询当前天气，返回温度和天气状况")
    public String getWeather(String city) {
        // 真实项目中调用第三方天气 API
        return "北京 · 晴 · 26°C";
    }
}

@RestController
class AgentController {

    private final ChatClient chatClient;
    private final WeatherTools weatherTools;

    // 构造器注入 ...

    @GetMapping("/ask")
    public String ask(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)
                .tools(weatherTools)        // 注册工具，框架自动处理调用循环
                .call()
                .content();
    }
}

4.2 LangChain4j

// 依赖（不依赖 Spring 也能用）

<dependency>
  <groupId>dev.langchain4j</groupId>
  <artifactId>langchain4j-open-ai</artifactId>
  <version>1.0.0-beta1</version>
</dependency>

// 简单 Chat（显式 Builder 拼装）

public class SimpleChat {
    public static void main(String[] args) {
        ChatLanguageModel model = OpenAiChatModel.builder()
                .apiKey(System.getenv("OPENAI_API_KEY"))
                .modelName("gpt-4o-mini")
                .temperature(0.3)
                .build();

        String answer = model.generate("用一句话解释什么是 RAG");
        System.out.println(answer);
    }
}

// Tool Calling：@Tool + AiServices 声明式接口

class WeatherTools {

    @Tool("根据城市名查询当前天气")
    public String getWeather(@P("城市名，如 北京、上海") String city) {
        return city + " · 晴 · 26°C";
    }
}

interface Assistant {
    String chat(String userMessage);
}

public class AgentDemo {
    public static void main(String[] args) {
        ChatLanguageModel model = OpenAiChatModel.builder()
                .apiKey(System.getenv("OPENAI_API_KEY"))
                .modelName("gpt-4o-mini")
                .build();

        Assistant assistant = AiServices.builder(Assistant.class)
                .chatLanguageModel(model)
                .tools(new WeatherTools())   // 注入工具
                .build();

        System.out.println(assistant.chat("北京今天天气怎么样？适合穿什么？"));
    }
}

口述要点

  • Spring AI 通过 Starter 自动装配 ChatClient.Builder，Controller 里直接注入即可。
  • LangChain4j 通过 Builder 显式构造 ChatLanguageModel，不依赖容器也能跑 main 方法。
  • 两者都用 @Tool 注解描述函数，但 LangChain4j 额外用 @P 描述参数，schema 更精确。
  • LangChain4j 的 AiServices 让"一个 Java interface + 注解"即可成为 Agent，是其招牌体验。

五、选型决策树 8 min

拿到一个新项目，按顺序问自己下面几个问题。每个叶子节点给出了推荐框架与理由。

  • Q1：项目已经是（或确定是）Spring Boot 技术栈？
    • 是 → 继续 Q2
      • Q2：对可观测性、配置中心、Security、事务等企业能力要求高？
        • 是：选 Spring AI Micrometer 原生、Advisors 与 Spring 生态无缝。
        • 否 → Q3
          • Q3：需要用到某个长尾向量库 / 模型 / 工具集成，Spring AI 尚未覆盖？
            • 是：选 LangChain4j 组件覆盖最广，可先在 Spring Boot 中以 starter 方式接入。
            • 否：Spring AI 仍然是默认选项，团队学习成本最低。
    • 否（Quarkus / Micronaut / CLI / 桌面 / Android / 纯 main）→ 继续 Q4
      • Q4：需要在没有 Spring 容器的环境运行？ → 直接选 LangChain4j，框架无关、依赖少、启动快。
  • 兜底：两者都能满足时 → 团队熟悉谁就选谁。Spring 团队优先 Spring AI；已经有 LangChain（Python）经验或希望跨语言复用概念，优先 LangChain4j。

反模式（不要这样选）

  • 仅仅因为"LangChain4j 名字像 LangChain"就在 Spring Boot 企业项目里默认选它——会损失大量开箱即用的可观测性。
  • 仅仅因为"Spring AI 是官方"就在非 Spring 环境里硬塞 Spring 容器——为了用一个库引入一整套框架，得不偿失。
  • 两个框架混用在同一条调用链上（例如 RAG 检索用 LangChain4j、对话用 Spring AI）——抽象重复、调试困难，除非有明确理由。

六、口述练习清单 5 min

下面 5 个问题是"Spring AI vs LangChain4j 选型"主题的第一梯队面试题。请合上笔记，用手机录音，每题控制在 60–90 秒，回听检查是否有结巴、漏点、自相矛盾。

请用 30 秒介绍一下 Spring AI 和 LangChain4j，它们分别解决什么问题？ 答题骨架：都是 JVM 上的 LLM 应用框架；Spring AI 由 Spring 官方出品、Spring 原生；LangChain4j 社区驱动、框架无关、灵感来自 LangChain。落点：让 Java 工程师用熟悉的方式做 Chat / Tool / RAG / Agent。
两者在架构哲学上最大的差异是什么？这会带来什么工程影响？ 关键词：声明式/约定优于配置 vs 工具箱/显式组装；Spring Boot 自动装配 vs Builder 模式；影响：项目启动速度、可观测性默认值、组件可替换粒度、团队学习曲线。
在 Tool Calling（函数调用）这件事上，两者的写法有什么异同？ 共同点：都用 @Tool 注解 + description 暴露方法，框架自动生成 JSON Schema 并处理 LLM 的调用循环。差异：Spring AI 用 ChatClient.tools(bean) 注册；LangChain4j 用 AiServices.builder().tools(...)，且支持 @P 描述参数、可用普通 interface 声明 Agent。
一个新项目要在两者之间做选型，你会怎么决策？ 按决策树回答：先问是不是 Spring Boot；再问企业能力 / 可观测性要求；再看所需模型或向量库是否被覆盖；非 Spring 环境默认 LangChain4j；兜底看团队经验。给一个反例说明不要只看名字或"官方"标签。
RAG 和 MCP 这两个能力，两个框架支持得如何？ RAG：Spring AI 走 Advisor 拦截器链（QuestionAnswerAdvisor / RetrievalAugmentationAdvisor），风格统一；LangChain4j 走 EmbeddingStore + Retriever + Reranker 模块化拼装，可替换粒度更细、向量库覆盖更多。MCP：Spring AI 有官方 spring-ai-mcp，同时支持 client/server；LangChain4j 有 langchain4j-mcp，支持 stdio/HTTP/SSE client，框架无关。两者都已进入可用阶段。

练习建议：第一遍看提示作答；第二遍只看题目；第三遍对着同事或橡皮鸭讲。三遍及以上，基本能在面试中稳定输出。
