# Skill: 路线图任务自动拆解

> 定时任务从路线图 HTML 中自动拆解学习任务，确保飞书清单始终保持 9 个未完成任务（今天3 + 明天3 + 后天3）。不再使用 backlog.json，每次直接从路线图生成。

## 适用场景

定时任务每日维护流程中，当飞书未完成任务数 N < 9 时，需要补充新任务。无论是否有新完成的任务（C=0 也触发），只要未完成任务不足 9 个，就从路线图 HTML 按 Phase 拆解尚未创建的学习任务来补满。

## 核心原则

### 1. 循序渐进

- 严格按 Phase 顺序拆解，**禁止跨 Phase 创建任务**
- Phase 0 未全部完成时，不得创建 Phase 1 任务
- 同一 Phase 内，按核心内容列表顺序拆解
- 每个任务应是前一个的自然延伸，不是跳跃式

### 2. 粒度控制

- **单个任务学习时长 ≤ 1 小时（极限 1.5 小时）**
- 如果一个核心内容点需要 > 1.5 小时，拆成 2~3 个子任务
- 拆分维度：按知识点拆（如"文档解析"→"PDF解析"+"表格提取"）、按层次拆（如"混合检索"→"BM25原理"+"向量+BM25融合"）
- **禁止出现内容爆满的单任务**（如"RAG 全链路实战"这种包揽一切的）

### 3. 框架开箱优先（任务形态控制，2026-09-03 用户要求）

- 拆解每个任务前，**先判断 Spring AI / LangChain4j 是否提供开箱实现**（如 TokenTextSplitter、RewriteQueryTransformer、QueryAugmenter、Advisor 体系、ChatMemory、QuestionAnswerAdvisor 等）
- **有开箱实现 → 任务形态必须是"框架组件接入 + 参数调优"**（如"Spring AI QueryAugmenter 接入与 Token 预算调优"），**禁止生成手写实现任务**
- **版本意识**：搜索确认框架最新稳定版本（Spring AI / LangChain4j），新版本新增的开箱实现优先采用；任务的 summary / description 中标注所依赖的框架与版本（如 "Spring AI 1.1.x QueryAugmenter"）。旧版本需要手写的做法若在新版本已有开箱替代，任务按新版本开箱用法出
- 手写实现任务的严格前提（**两者缺一不可**）：
  1. 框架确实无开箱实现
  2. 企业对该功能的实现普遍手写（如引用溯源角标、拒答阈值判断）
- 即使满足前提允许手写，任务也只需"**讲清原理 + 最小可运行示例**"，禁止要求学习底层逐行实现（原理深度留给面试口述，不进编码作业）

### 4. 去重

- 创建前必须检查 snapshot.json 中已存在的任务列表
- 按任务 summary 的关键词匹配，避免重复创建
- 已完成和未完成的任务都不应重复

### 5. 数量控制

- 每次只创建补满 9 窗口所需数量的任务，不多创建
- 需要补充的任务数 G = max(0, 9 - N)，其中 N = 飞书当前未完成任务数
- **无论 C=0 还是 C>0，只要 N < 9 就拆解补充**（C=0 也触发拆解）
- 如果当前 Phase 核心内容已全部拆解但仍不足 9 个，检查验收标准，可进入下一 Phase
- 如果路线图已到末尾或无法再拆解，**有多少创建多少，不凑数**

## 拆解流程

```
1. 统计飞书当前未完成任务数 N，计算需要补充的任务数 G = max(0, 9 - N)。若 G=0 则跳过。
2. 确定当前 Phase（根据天数计算：Phase0=第1-14天, Phase1=第15-56天, Phase2=第57-98天...）
3. 解析路线图 HTML 中该 Phase 的"核心内容"列表
4. 读取 snapshot.json，标记已创建的任务（已完成 + 未完成）
5. 对比核心内容与已创建任务，找出尚未覆盖的知识点
6. 对每个未覆盖知识点，先确认 Spring AI / LangChain4j 最新稳定版本的开箱实现情况（见原则3），再拆解为 G 个合适粒度的任务（≤1h/个）：
   - 有开箱实现 → 任务形态为"框架组件接入 + 参数调优"，标注框架与版本
   - 无开箱实现且企业普遍手写 → 任务形态为"原理讲清 + 最小可运行示例"
7. 每个任务编写完整 description（见下方格式）
8. 创建到飞书，created_at 设为当前时间戳
```

## 任务 Description 格式

每个任务的 description 必须包含以下结构：

```
【学习目标】该任务对应PhaseX，目标是...
【知识点】关键词1/关键词2/关键词3
【学习资源】资源名: URL ; 资源名: URL
【验收标准】能口述.../能写出.../能跑通...
【相关面试题】题目名（第X梯队）
```

## Phase 核心内容索引

### Phase 0（第1-14天）定向与双框架地基

核心内容：
- Spring AI ChatClient / Advisors / Tool Calling / 可观测性（Micrometer）
- 本地 Ollama 部署 Qwen，PGVector 或 Milvus 本地起
- Spring AI vs LangChain4j 选型对比笔记

验收标准：能口述 Spring AI 与 LangChain4j 各自优劣与选型场景；本地 demo 跑通"提问→检索本地文档→回答"；目标 JD 清单 + 刚需提取表完成。

### Phase 1（第15-56天）RAG 刚需闭环 + 生产级项目1

核心内容：
- 文档解析（PDF/Word/表格）→ 智能切分（多粒度）→ Embedding
- 混合检索（向量+BM25）→ Rerank → 上下文组装 → 引用防幻觉
- RAG 评测：Recall@K / nDCG / LLM-as-Judge

验收标准：能讲清"为什么 pgvector 够用/混合检索 recall 提升多少/rerank 延迟代价/评测怎么设计"；GitHub 项目含完整工程结构+README+决策文档；评测报告有改切分/加 rerank 前后的真实对比数字。

### Phase 2（第57-98天）工程化补齐 + Agent 进阶 + 项目2

核心内容：
- SpringCloud（Nacos/Gateway/OpenFeign）；Redis 会话记忆+缓存；MQ 异步文档入库
- ReAct / Plan-Execute；Multi-Agent；MCP 协议（写一个 MCP Server）
- 流式输出 SSE；令牌桶限流；Micrometer 全链路追踪

### Phase 3（第99-140天）面试"造飞机"冲刺

核心内容：
- 第一梯队 10 道硬骨头（见面试体系）
- 第二梯队加分项；各公司面经
- 每题三步：翻车点→原理→合上资料自己复述

## 面试题关联规则

创建任务时，从路线图面试体系中匹配相关面试题：

- 第一梯队：Attention公式、Function Call底层、ReAct死循环防护、RAG完整链路+Chunking、混合检索+Rerank、Agent记忆系统、MCP vs Function Call、RAG评测三层指标、Agent vs Workflow、Spring AI vs LangChain4j选型
- 第二梯队：按任务主题从第二梯队列表中匹配

## 贯穿线任务

除了 Phase 核心内容，还有两条贯穿线：

- **Python 脚本级补齐**（Phase 1 起并行）：语法、requests/pandas、调用大模型API
- **技术决策日志**（全程）：每次技术选型记"为什么选它/放弃了什么/代价是什么"

贯穿线任务每 3-4 天穿插一个，与 Phase 核心任务交替出现，避免连续多天只学同一主题。

## 错误处理

- 如果路线图 HTML 解析失败，记录日志，不创建新任务（飞书保持现有任务不变）
- 如果新任务创建失败，记录错误，继续创建下一个
- 不得因为任务生成失败而中断整个定时任务流程
