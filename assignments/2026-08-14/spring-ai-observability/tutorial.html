一、依赖与 Actuator 端点

在已有 Spring AI 项目（Spring Boot 3.3+ / Spring AI 1.0+）上加两个依赖：

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>

application.yml 暴露指标端点：

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: always
  metrics:
    tags:
      application: ${spring.application.name:rag-demo}
  observations:
    annotations:
      enabled: true

spring:
  ai:
    chat:
      client:
        observations:
          log-prompt: false
          log-completion: false
    chat:
      observations:
        log-prompt: false
        log-completion: false
为什么默认关闭 prompt/completion 日志
prompt 和 completion 是高基数数据，可能含敏感信息。Spring AI 默认不导出，只在 trace 中可见。开发环境可临时开启排查问题，生产环境务必保持关闭，通过独立日志 advisor 脱敏后再记录。

二、ChatClient 自动产生的指标

启动应用，调用一次 ChatClient 后访问：

curl -s http://localhost:8080/actuator/metrics/gen_ai.client.operation.duration | jq
curl -s http://localhost:8080/actuator/metrics/gen_ai.client.token.usage  | jq

Spring AI 自动注册的核心指标（命名遵循 OpenTelemetry GenAI 语义约定）：

指标名类型用途
gen_ai.client.operation.durationTimer每次 ChatClient 调用耗时，含 model/operation 标签
gen_ai.client.token.usageDistributionSummary输入/输出 token 数，按 gen_ai.token.type=input/output 区分
gen_ai.client.request.countCounter调用总次数（1.0+ 版本合并到 duration 统计中）
spring.ai.chat.clientObservationChatClient.call/stream 的完整 span，可接入 Zipkin/Tempo

三、Advisor 链路中的可观测维度

QuestionAnswerAdvisor / RetrievalAugmentationAdvisor 在调用向量库时会产生 spring.ai.vector.store observation，包含：

  • db.system：pgvector / qdrant / milvus 等
  • db.operation：similarity_search / add
  • spring.ai.vectorstore.dimension：向量维度
  • 耗时：能定位"检索慢"还是"模型慢"

这是 Phase 1 做 RAG 性能调优的重要入口 —— 一旦 rerank 加上去，能在 trace 里看到检索、rerank、LLM 三段各自的耗时分布。

四、自定义成本统计（可选，10 分钟）

对于按 token 计费的模型，注册一个 ObservationHandler 把 token 数乘以单价落到自定义 counter：

@Component
public class CostObservationHandler implements ObservationHandler<Observation.Context> {

    private final MeterRegistry registry;
    private final double inputPricePerToken  = 0.0000025;  // USD
    private final double outputPricePerToken = 0.00001;

    public CostObservationHandler(MeterRegistry registry) {
        this.registry = registry;
    }

    @Override
    public boolean supportsContext(Observation.Context context) {
        return context instanceof ChatModelObservationContext;
    }

    @Override
    public void onStop(Observation.Context context) {
        ChatModelObservationContext ctx = (ChatModelObservationContext) context;
        if (ctx.getResponse() == null
            || ctx.getResponse().getMetadata() == null
            || ctx.getResponse().getMetadata().getUsage() == null) {
            return;
        }
        Usage usage = ctx.getResponse().getMetadata().getUsage();
        double cost = usage.getPromptTokens()     * inputPricePerToken
                    + usage.getCompletionTokens() * outputPricePerToken;
        registry.counter("llm.cost.usd",
                "model", ctx.getChatOptions().getModel())
                .increment(cost);
    }
}

访问 /actuator/metrics/llm.cost.usd 即可看到累计成本。

五、本地验收脚本

# 1. 发一次对话
curl -X POST http://localhost:8080/chat -H 'Content-Type: application/json' \
     -d '{"message":"用一句话解释 RAG"}'

# 2. 确认 token 指标存在
curl -s http://localhost:8080/actuator/metrics/gen_ai.client.token.usage \
  | grep -q '"name"' && echo "OK: token metric"

# 3. 确认 duration 指标存在
curl -s http://localhost:8080/actuator/metrics/gen_ai.client.operation.duration \
  | grep -q '"name"' && echo "OK: duration metric"

# 4. Prometheus 端点可被抓取
curl -s http://localhost:8080/actuator/prometheus | grep gen_ai && echo "OK: prometheus"

六、面试话术（1 分钟口述）

  1. Spring AI 1.0 基于 Micrometer Observation，自动产出 gen_ai.client.* 指标，不需要 AOP。
  2. Token 用量通过 gen_ai.client.token.usage 拿到，用 input/output tag 拆分，乘以单价就是成本。
  3. ChatClient / Advisor / VectorStore 三层都有独立 observation，接 Tempo/Zipkin 后能看到检索慢还是 LLM 慢。
  4. Prompt/completion 默认不导出，避免敏感信息泄漏；要调试用独立日志 advisor。
