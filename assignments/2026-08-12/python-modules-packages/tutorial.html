阶段一 · pip 基础

建议时长：15 min

pip 是 Python 的官方包安装器，从 PyPI（Python Package Index）解析并下载"分发包（distribution package）"。它相当于 Java 世界里 Maven / Gradle 用来拉取 jar 依赖的客户端，但 pip 本身不做完整的"构建生命周期"，只负责"安装—解析—卸载"。

1.1 确认 pip 可用

推荐始终通过 python -m pip 调用，以确保使用的是当前 Python 解释器对应的 pip，避免多版本共存时的混淆：

# Linux / macOS
python3 --version
python3 -m pip --version

# Windows（使用 py 启动器）
py --version
py -m pip --version

1.2 安装、升级、卸载包

# 安装最新版本
python -m pip install requests

# 安装指定版本（版本锁定）
python -m pip install "requests==2.32.3"

# 安装最低版本
python -m pip install "requests>=2.30.0"

# 升级到最新版
python -m pip install --upgrade requests

# 卸载（会交互式确认）
python -m pip uninstall requests

# 查看已安装包
python -m pip list
python -m pip show requests
提示：建议把 python -m pip install --upgrade pip 作为每个新环境的第一条命令，旧版 pip 的依赖解析器在复杂依赖图下容易出错。

1.3 requirements.txt：可复现安装

requirements.txt 是 pip 世界最常见的"依赖清单"，等价于 Maven 的 pom.xml 中 <dependencies> 的扁平列表，但它不区分 scope / 可选依赖等高级元数据。

# 1) 冻结当前环境的精确版本
python -m pip freeze > requirements.txt

# 2) 在新环境中复现
python -m pip install -r requirements.txt

一个典型的 requirements.txt：

requests==2.32.3
flask>=3.0.0,<4.0.0
python-dotenv~=1.0.0
pytest
# 也可以直接从 Git 安装
# git+https://github.com/psf/requests.git@main

Java 对比：pip vs Maven / Gradle

维度Python（pip + PyPI）Java（Maven / Gradle + Maven Central）
包仓库 PyPI（pypi.org），任何人可上传 Maven Central，需签名并发布到 Sonatype OSSRH
依赖清单 requirements.txt（扁平）或 pyproject.toml pom.xml（XML）或 build.gradle（Groovy/Kotlin DSL）
版本约束 ==, >=, ~=, < 等说明符 语义化版本区间 / 动态版本（1.+, latest.release）
传递依赖 pip 20.3+ 启用新解析器（resolver），一次性求解 Maven / Gradle 都有成熟的依赖调解与冲突解决
构建生命周期 pip 只负责安装；构建由 build backend（setuptools/hatchling 等）承担 Maven 内置 compile/test/package/install/deploy 生命周期
制品格式 wheel（.whl，已构建）/ sdist（.tar.gz，源码） JAR / WAR / EAR（本质都是 zip + 字节码）

1.4 常见坑

  • 不要用 sudo pip install：会污染系统 Python，可能破坏 OS 工具链。Linux 发行版（如 Ubuntu）依赖系统 Python 运行包管理器，误升级会导致系统异常。
  • pip 不是虚拟环境：pip 负责"装包"，venv 负责"隔离"，二者配合使用。
  • 国内网络：可用 python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple somepkg 临时切换镜像。

阶段二 · venv 虚拟环境

建议时长：15 min

venv 是 Python 3.3+ 标准库内置的虚拟环境模块（PEP 405）。它为每个项目创建一个独立目录，里面包含独立的 Python 解释器副本/符号链接、独立的 site-packages，从而实现项目级依赖隔离。

2.1 创建与激活

# 在项目根目录创建名为 .venv 的虚拟环境（约定俗成）
python3 -m venv .venv

# ---- Linux / macOS（bash/zsh）----
source .venv/bin/activate

# ---- Windows（cmd.exe）----
.venv\Scripts\activate.bat

# ---- Windows（PowerShell）----
.venv\Scripts\Activate.ps1

激活后，shell 提示符前会出现 (.venv)，此时：

  • python / pip 自动指向虚拟环境内的版本；
  • 所有 pip install 的包都装进 .venv/lib/pythonX.Y/site-packages/；
  • 系统 Python 和全局 site-packages 不受影响。

2.2 退出与删除

# 退出虚拟环境
deactivate

# 彻底删除（虚拟环境是"可抛弃资源"）
rm -rf .venv            # Linux / macOS
rmdir /s /q .venv       # Windows cmd
重要约定：把 .venv/ 加入 .gitignore，绝不要提交到 Git。虚拟环境应当可以通过 requirements.txt 或 pyproject.toml 在任何机器上一键重建。

2.3 完整工作流

# 1. 新建项目
mkdir myapp && cd myapp

# 2. 创建并激活虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 3. 升级 pip 并安装依赖
python -m pip install --upgrade pip
python -m pip install requests flask

# 4. 固化依赖
python -m pip freeze > requirements.txt

# 5. 协作者拿到代码后
git clone https://example.com/myapp.git
cd myapp
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

2.4 venv 是怎么工作的

创建后的目录结构大致如下：

.venv/
├── pyvenv.cfg                # 指向 base Python 解释器路径
├── bin/                      # Linux/macOS：python、pip、activate 脚本
│   ├── activate
│   ├── activate.fish
│   ├── pip
│   └── python -> /usr/bin/python3
├── Include/
├── Lib/                      # Windows 上的 site-packages
└── lib/
    └── python3.12/
        └── site-packages/    # 该项目独立的第三方包
            ├── requests/
            └── flask/

pyvenv.cfg 中的 home 键指向 base Python，虚拟环境通过它继承标准库，但 site-packages 是独立的。这就是为什么"虚拟环境很轻"——它不复制整个标准库。

Java 对比：venv vs classpath / JPMS 模块化

Java 早期靠 CLASSPATH 环境变量或 -cp 参数告诉 JVM 去哪里找 .class / .jar，没有强制的项目级隔离，"classpath hell"（同名类多版本冲突）是经典痛点。Maven / Gradle 通过"每个项目独立的本地仓库 + 构建时依赖解析"缓解了这一问题，而 Java 9（2017）引入的 JPMS（module-info.java）则在语言层加入了模块化。

维度Python venvJava classpath / JPMS
隔离单元 一个目录（.venv），包含解释器 + site-packages JVM 进程的 classpath；JPMS 下是 module path
激活方式 source activate，修改当前 shell 的 PATH 启动 JVM 时通过 -cp / -p 传入；IDE 运行配置
多版本并存 每个项目一个 venv，互不影响 同一 JVM 内同一全限定类只能有一个版本；靠 Maven 依赖调解
语言层模块 模块 = .py 文件，包 = 含 __init__.py 的目录 JPMS module-info.java 声明 requires / exports
封装边界 下划线前缀（_name）是约定俗成的"私有" 未 exports 的包在模块外不可访问，由编译器和 JVM 强制

一句话：venv 解决的是"项目之间的依赖版本隔离"，JPMS 解决的是"大型应用内部的模块边界与封装"，两者不在同一层。Python 的包结构（下一节）承担了类似 JPMS 在源码组织层面的作用。

2.5 常用参数速查

python -m venv .venv                 # 标准创建
python -m venv --system-site-packages .venv   # 可见系统 site-packages（不推荐）
python -m venv --prompt myapp .venv  # 自定义提示符前缀
python -m venv --upgrade .venv       # base Python 升级后，刷新环境链接

阶段三 · 包结构与 __init__.py

建议时长：10 min

3.1 模块与包的定义

  • 模块（module）：一个 .py 文件就是一个模块。文件名（去掉 .py）就是模块名。
  • 包（package）：一个含 __init__.py 的目录（Python 3.3 起也支持无该文件的"命名空间包"，但常规包仍推荐保留）。
  • 导入（import）：把其它模块中的函数、类、变量引入当前命名空间。

3.2 典型目录结构

myproject/
├── pyproject.toml            # 现代打包配置（PEP 621）
├── README.md
├── requirements.txt
├── src/
│   └── mypackage/
│       ├── __init__.py       # 包初始化文件，可以为空
│       ├── __main__.py       # 支持 python -m mypackage 入口
│       ├── core.py
│       ├── utils.py
│       └── subpkg/
│           ├── __init__.py
│           └── helpers.py
└── tests/
    ├── __init__.py
    └── test_core.py

3.3 __init__.py 的作用

  1. 标识包：让 Python 把该目录识别为常规包（regular package）。
  2. 初始化代码：包被首次导入时执行一次，可用于设置日志、注册插件。
  3. 暴露公共 API：把子模块中的符号"提升"到包顶层。
  4. 定义 __all__：控制 from package import * 时导入哪些名字。
# src/mypackage/__init__.py
"""mypackage 的顶层说明。"""

__version__ = "0.1.0"

# 把子模块中的常用对象提升到包顶层
from .core import Processor, process_data
from .utils import normalize

__all__ = ["Processor", "process_data", "normalize", "__version__"]
# src/mypackage/core.py
def process_data(items):
    return [x for x in items if x is not None]

class Processor:
    def __init__(self, name):
        self.name = name
    def run(self, data):
        return process_data(data)

使用者就可以这样写：

import mypackage

# 直接从包顶层拿到，而不必写 mypackage.core.Processor
p = mypackage.Processor("demo")
result = p.run([1, None, 2, None, 3])
print(result)                       # [1, 2, 3]
print(mypackage.__version__)        # 0.1.0

3.4 绝对导入 vs 相对导入

# src/mypackage/subpkg/helpers.py

# 绝对导入（推荐，可读性好）
from mypackage.utils import normalize

# 相对导入（仅在包内部使用）
from ..core import Processor         # 上级包
from . import sibling_module         # 同级模块
经验法则：对外发布的库用绝对导入；包内部深层模块可用单点相对导入（from . import x），避免超过两层的 ..，否则会让结构变得难读。

3.5 入口：__main__.py 与 if __name__ == "__main__"

# src/mypackage/__main__.py
from .core import Processor
import sys

def main():
    name = sys.argv[1] if len(sys.argv) > 1 else "world"
    print(f"hello, {name}")

if __name__ == "__main__":
    main()

# 运行方式：
#   python -m mypackage Alice

if __name__ == "__main__": 是 Python 的标准惯用法：当文件被直接运行时 __name__ 为字符串 "__main__"；当被 import 时则是模块名。用它可以让同一个文件既"可执行"又"可导入"。

3.6 现代打包：pyproject.toml 一瞥

# pyproject.toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "mypackage"
version = "0.1.0"
description = "A demo package"
requires-python = ">=3.9"
dependencies = [
    "requests>=2.30.0",
]

[project.optional-dependencies]
dev = ["pytest>=7.0", "ruff"]

安装为可编辑模式（开发期常用）：

python -m pip install -e ".[dev]"

Java 对比：Python 包结构 vs Java 包 + Maven 目录约定

维度PythonJava
命名空间 由目录层级决定（mypackage.subpkg.helpers） 由 package 声明 + 目录层级决定（com.example.utils）
目录即包 需要 __init__.py（或命名空间包） 目录结构必须与 package 声明一致
构建配置 pyproject.toml（[project] 表声明依赖） pom.xml / build.gradle（<dependencies> / dependencies {}）
源码布局 推荐 src layout（src/mypackage/） 约定 src/main/java、src/test/java
可执行入口 __main__.py + python -m pkg；或 console_scripts public static void main(String[] args)；可执行 JAR 的 Main-Class

阶段四 · 标准库速览

建议时长：10 min

Python 自称"batteries included（自带电池）"，标准库覆盖面极广，绝大多数日常任务无需第三方依赖。下面按场景分组，建立心智地图；用到时再深入查文档即可。

4.1 文件与系统

模块用途
os / sys操作系统接口、解释器信息、sys.argv、sys.path
pathlib面向对象的路径操作（推荐优先于 os.path）
shutil高阶文件操作：复制、移动、删除目录树
globUnix 风格路径通配符匹配（*.txt）
tempfile临时文件和目录
 
from pathlib import Path
import shutil

# 列出当前目录下所有 .py 文件
for p in Path(".").glob("*.py"):
    print(p.resolve())

# 递归创建目录
Path("out/data").mkdir(parents=True, exist_ok=True)

# 安全的临时目录
with tempfile.TemporaryDirectory() as tmp:
    ...

4.2 数据处理与文本

模块用途
jsonJSON 解析与序列化（对标 Java Jackson/Gson 的基础能力）
csvCSV 读写
re正则表达式
datetime日期时间，推荐 date / time / datetime / timedelta
collectionsdefaultdict、Counter、deque、namedtuple
itertools高效迭代器：chain、groupby、product、combinations
functoolslru_cache、partial、reduce、wraps
 
import json
from collections import Counter
from functools import lru_cache

data = json.loads('{"name": "alice", "scores": [90, 85, 95]}')
print(data["name"], sum(data["scores"]) / len(data["scores"]))

words = "apple banana apple cherry banana apple".split()
print(Counter(words).most_common(2))   # [('apple', 3), ('banana', 2)]

@lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

4.3 网络与并发

模块用途
urllib.requestHTTP 客户端（低层；第三方 requests 更易用）
http.server快速起一个静态文件服务器（python -m http.server）
socket原始 TCP/UDP 套接字
threading / multiprocessing线程 / 进程并行
concurrent.futuresThreadPoolExecutor / ProcessPoolExecutor 高层 API
asyncio事件循环 + async/await 协程
subprocess调用外部命令，捕获输出
 
import subprocess
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    r = subprocess.run(
        ["curl", "-s", "-o", "/dev/null", "-w", "%{http_code}", url],
        capture_output=True, text=True,
    )
    return url, r.stdout

with ThreadPoolExecutor(max_workers=4) as pool:
    for url, code in pool.map(fetch, [
        "https://www.python.org",
        "https://pypi.org",
        "https://docs.python.org",
    ]):
        print(code, url)

4.4 测试、调试与质量

  • unittest：内置单元测试框架（风格接近 JUnit）。
  • doctest：从文档字符串中的交互式示例运行测试。
  • logging：标准日志库，支持 handler / formatter / level。
  • pdb：交互式调试器，breakpoint() 进入。
  • argparse：命令行参数解析。
  • typing：类型提示（TypeHint），配合 mypy / pyright 静态检查。
# test_demo.py
import unittest
from mypackage.core import Processor

class TestProcessor(unittest.TestCase):
    def test_run_filters_none(self):
        p = Processor("demo")
        self.assertEqual(p.run([1, None, 2]), [1, 2])

if __name__ == "__main__":
    unittest.main()

# 运行：python -m unittest -v

4.5 一张心智图

Python 标准库
├── 文件系统     os, pathlib, shutil, glob, tempfile
├── 数据/文本    json, csv, re, datetime, collections, itertools, functools
├── 网络并发     urllib, http.server, socket, threading, asyncio, subprocess
├── 质量保障     unittest, doctest, logging, pdb, argparse, typing
├── 算法/数学    math, random, statistics, decimal, fractions
├── 压缩归档     zipfile, tarfile, gzip
└── 其他实用     dataclasses, enum, abc, contextlib, copy, pprint
学习建议：本阶段目标是"知道有什么"，而非"记住所有 API"。能在 30 秒内想到"这个需求标准库是否已经有现成模块"，就已经达成 Phase 0 地基目标。写代码时优先查标准库，再考虑第三方包。
