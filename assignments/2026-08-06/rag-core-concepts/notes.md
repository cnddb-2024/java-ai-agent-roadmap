# RAG 核心概念学习笔记

## 一、Embedding 原理

在最初的离线阶段，就可以将准备好的资料进行分割成 chunk 切片，再通过 embedding 模型进行向量化后存入 embedding 向量数据库。

简单来说就是将文字转化成一组组的高维向量，将这些向量和原切片一起存入向量数据库。检索时通过 query 问题与切片的两个向量的余弦相似度来判断语义是否相关。

**关键点：**
- 离线阶段完成，不影响在线查询性能
- chunk 分割是基础，影响检索粒度
- embedding 模型决定向量质量
- 余弦相似度衡量语义相似性

## 二、向量检索

将处理过后的用户问题向量化后，与向量数据库内的切片进行余弦相似度的计算，越接近的说明语义相关，检索出来。

**关键点：**
- 在线阶段执行
- query 向量化使用与离线阶段相同的 embedding 模型
- 余弦相似度计算：cos(A, B) = (A·B) / (|A| × |B|)
- 这是粗排阶段，召回率高但精度有限

## 三、重排序（Reranking）

通过上一步的初步检索一般只进行了粗排，即可能会检索出一些看似相关实则不是想要的数据，还需进行进一步的精排即重排序。

这一步可以通过更慢但更精准的步骤来筛选出真正相关的切片（可以使用 score 模型等）。

**关键点：**
- 精排阶段，在粗排结果上进一步筛选
- 使用更复杂/更精准的模型（如 cross-encoder score 模型）
- 速度更慢但准确率更高
- 通常对粗排 Top-K 结果做重排序，而非全量

## 四、生成

最终将切片及处理过后的用户问题一起发给 LLM，要求 LLM 回答时可以引用相关的资料，如不相关则不予回答。

**关键点：**
- 将检索到的 chunk 作为 context 传入 prompt
- LLM 基于 context + question 生成回答
- 可要求引用来源，增强可信度
- 不相关时拒绝回答，减少幻觉

## 五、RAG 的核心价值

一句话来说 RAG 就是企业用来搭建 AI 知识库的最佳实践，原因有二：

1. **知识可以热更新**：直接向量化入数据库就行，无需重新训练或微调模型
2. **错误需要勘正的数据可以追溯到切片 chunk 的元数据**：这样就可以定位是哪一部分知识出错了

## 六、完整流程图

```
离线阶段：
  资料 → chunk 分割 → embedding 向量化 → 存入向量数据库

在线阶段：
  用户提问 → 向量化 → 向量检索（粗排）→ 重排序（精排）→ 生成回答
```
